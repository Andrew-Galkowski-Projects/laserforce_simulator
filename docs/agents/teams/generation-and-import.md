# teams: generation and roster import

Bulk generation (LG-00, `POST /api/teams/generate/`), League-spread tiered generation (CRE-02) and the CSV roster import (LG-00b, `POST /api/teams/import/` + `GET /api/teams/import/template/`).
Moved verbatim from `laserforce_simulator/teams/CLAUDE.md`; the app index there points here.

## LG-00 generation

Bulk player/team generation: service `teams.services.run_player_generation`, form `teams/forms.py::GenerateLeagueForm`. Two output modes selected by the form's `num_teams` value: `num_teams ≥ 1` creates new **Teams** with auto-filled 6-slot rosters + optional bench when `players_per_team > 6`; `num_teams == "0"` creates a flat free-agent pool of 12–100 players on the reserved **Free Agents Team** (GLOSSARY.md — magic name `"Free Agents"`, no `is_system` field, no model change, no migration).

**Pure generation module.** `teams/player_generator.py` is the algorithmic seam — **pure Python, no Django imports, no ORM, no settings access, no I/O, no global RNG** (frozen import allowlist: `random` for `Random` type-hint only with the RNG **injected** by the caller, `typing` for annotations, optional `collections`). The "no Django imports leaked" defensive check mirrors the RES-04 / RV-03 / HX-01 / HX-02 / HX-03 / HX-04 precedent. The module's public surface is three functions:

- `draw_stats(rng: random.Random, mean: float, std_dev: float) -> dict[str, int]` — returns a dict with **exactly 19 keys** in the module-level `_STAT_FIELDS` canonical order (3 awareness + 1 decision + 5 physical + 2 team + 8 role); each value is `max(0, min(100, round(rng.gauss(mean, std_dev))))`. Draws are made in `_STAT_FIELDS` order to keep RNG consumption deterministic given a seeded `random.Random`. The module does **not** range-check `mean` / `std_dev` — that is the form's job.
- `draw_preferred_roles(rng) -> list[str]` — returns 1–3 unique role names drawn from the module-local `_ROLE_NAMES` tuple `("commander", "heavy", "scout", "medic", "ammo")` with a `70 / 20 / 10` count distribution. Implementation pin (so tests can assert RNG-consumption parity): `n = rng.choices([1, 2, 3], weights=[70, 20, 10], k=1)[0]` then `rng.sample(_ROLE_NAMES, n)`.
- `assign_slots(preferred_roles_per_player) -> dict[str, int | None]` — deterministic greedy bipartite match of the first 6 players to the 6-slot `_SLOT_KEYS` tuple `("commander", "heavy", "scout_1", "scout_2", "medic", "ammo")`. Canonical-slot-first iteration; the slot's role is the key with any trailing `"_1"` / `"_2"` stripped (so both Scout slots want `"scout"`); lowest-unassigned-player-index tie-break (pinned by `test_assign_slots_deterministic_tiebreak`); unmatched slots receive `None` and `teams.services._assign_team_slots` back-fills them with leftover players in ascending player-index order. **Pure: no `random` calls inside `assign_slots`** — the function is deterministic given its input.

**`_STAT_FIELDS` canonical order (frozen, 19 entries).** `player_awareness, game_awareness, resource_awareness, decision_making, positioning, stamina, speed, flexibility, adaptability, communication, teamwork, Offensive_synergy, defensive_synergy, midfield_synergy, resupply_synergy, resupply_efficiency, accuracy, survival, special_usage`. **`Offensive_synergy` is intentionally capital-O** — the existing field name on `Player` in `teams/models.py` uses that casing and the service's `Player(**stats)` splat requires the keys to match the field names byte-for-byte. The pure module hand-rolls `_ROLE_NAMES` and `_SLOT_KEYS` locally rather than importing `matches.sim_helpers.role_constants` — keeping `teams/player_generator.py` Django-free is the contract (the role-name strings happen to align with `PlayerRoundState.role` and `Player.preferred_roles` lowercase values).

**Form.** `GenerateLeagueForm` (`teams/forms.py`) has four fields: `num_teams` (`CharField` + `Select` widget, 22 choices `"0"` + `"2".."20"` + `"random_2_10"` — **`"1"` is deliberately omitted**), `players_per_team` (`CharField`; the accepted values are `"6".."9"` + `"random_team"` (team mode, `TEAM_MODE_PPT_CHOICES`) and `"12".."100"` + `"random_pool"` (pool mode, `POOL_MODE_PPT_CHOICES`) and `clean()` enforces the cross-field rule), `mean` (`IntegerField`, `min_value=0`, `max_value=100`, `initial=50`), `std_dev` (`IntegerField`, `min_value=1`, `max_value=40`, `initial=15`). Cross-field validation in `clean()` raises `forms.ValidationError` with locked wording — `"Players per team must be 12–100 when generating a free-agent pool"` when `num_teams == "0"` paired with anything outside `{"random_pool"}` ∪ `{12..100}`, and `"Players per team must be 6–9 when generating teams"` when `num_teams != "0"` paired with anything outside `{"6", "7", "8", "9", "random_team"}`. Tests substring-match the locked copy.

**Service.** `run_player_generation(cleaned_data, *, manager) -> GenerationResult(created_teams, free_agent_count)` is decorated `@transaction.atomic` — a mid-loop raise rolls back every Team and Player write. It takes a valid `GenerateLeagueForm`'s `cleaned_data`, resolves `random_*` markers via `random.randint(2, 10)` (`num_teams == "random_2_10"`) / `random.randint(6, 8)` (`players_per_team == "random_team"`) / `random.randint(12, 100)` (`players_per_team == "random_pool"`), builds a fresh `rng = random.Random()` (production uses fresh entropy; **no seed input field on the form, deliberately out of scope**), pre-shuffles copies of `TEAM_NAMES` and `PLAYER_NAMES`, and pops from them as Teams/Players are created via `_pop_unique_name` — a taken name (`Team` name globally, or `Player` name within the destination Team) is discarded and the next pool name tried (UXP-18); only when every remaining pool name is taken does the first one popped get `" #{k}"` with `k` incrementing from 2; on pool exhaustion fall back to `f"{POOL[-1]} #{n}"`.

**Regular-teams branch (`num_teams ≥ 1`, `_generate_teams`).** For each Team: pop a name + collision-check; `team = Team.objects.create(name=..., manager=manager)`. Each Player's kwargs come from `_build_player_kwargs`, which calls the existing `_random_player_profile()` helper (**NOT** refactored to accept a `name` parameter — `_build_player_kwargs` discards the helper's `name` field and the caller supplies the popped+deduped Player-pool name). Build stats with `draw_stats(rng, mean, std_dev)` and `preferred_roles` with `draw_preferred_roles(rng)`. Create each Player via `Player.objects.create(team=team, name=..., **profile_minus_name, **stats, preferred_roles=...)`. `_assign_team_slots` runs `assign_slots(...)` on the first 6 players' preferred_roles lists; for each `(slot_key, player_index)` entry set the matching FK on the Team (`scout_1` → `team.slot_scout_1`, etc.); for `None`-valued slot_keys, back-fill with leftover players (those whose index was never assigned) in ascending player-index order. After back-fill, all 6 slots are filled. Players 7+ (`players_per_team > 6`) are bench: created on the Team but never assigned to a `slot_*` FK. `team.save()` once after all slot FKs are set.

**Free-agents branch (`num_teams == "0"`, `_generate_free_agents`).** `free_agents = get_free_agents_team()`. Pop `players_per_team` player profiles (with per-team name collision-check against `free_agents` and the names already picked this run), built as above and written in one `Player.objects.bulk_create`. **Do NOT touch any `slot_*` FK on the Free Agents Team** — it stays an unfilled roster on purpose (`is_valid_roster` returns False, by design — the Free Agents Team is a player container, not a competitive roster).

**Manager + helper.** `teams/models.py` gains a new `TeamManager(models.Manager)` class with a single public method `regular()` returning `self.exclude(name="Free Agents")`, assigned as `objects = TeamManager()` on the `Team` class. **No migration** — managers are not schema; Django picks the swap up at class load. **`Team.objects.all()` is unchanged** and continues to include the Free Agents Team — the distinction is pinned by `test_objects_all_still_includes_free_agents`. A new module-level helper `get_free_agents_team() -> Team` is defined adjacent to the `Team` class (mirrors the existing `_random_player_profile` module-level pattern, **NOT** a classmethod — keeps the call-site grep `get_free_agents_team()` short and obvious) returning `Team.objects.get_or_create(name="Free Agents")[0]`. Idempotent across runs — the second call returns the same `pk`. The Free Agents Team has no `slot_*` FKs filled (`is_valid_roster` returns False, by design). The `GET /api/teams/` list applies `regular()` by default (**ANG-01a**; `?include_free_agents=true` opts back in) — **out of scope** to migrate other `Team.objects.all()` call sites (admin / `simulate_match`) since any code that iterates rosters or simulates against the Free Agents Team already fails the `is_valid_roster` gate.

**Constants.** `teams/constants.py` gains a new top-level `TEAM_NAMES: tuple[str, ...]` of 30–50 themed laser-tag team names — same shape and casing as the existing `PLAYER_NAMES` (module-scope `tuple[str, ...]` of plain strings, all entries unique, no surrounding whitespace). `TEAM_NAMES` is consumed by the generation services (`teams/services.py`, `matches/league_services.py`, `matches/tournament_services/create.py`); the pure module (`teams/player_generator.py`) does **NOT** import it per the pure-module import allowlist above.

**Determinism / scope.** The pure module never seeds a global `random` and never touches simulator RNG; `@transaction.atomic` covers the whole of `run_player_generation` so partial generation never persists. **No simulation behaviour change, no `_flush_to_db` touch, no SIM-07 / SIM-08 contract interaction, no Score Calibration re-baseline obligation, no model field change, no migration, no ADR** (decisions are reversible — manager-class swap + module-level helper + pure module). **Out of scope (deliberate):** no per-stat or per-role bell-curve presets (a single `mean`/`std_dev` covers all 19 stats); no `is_system` Team field (Free Agents identified by magic name only); no preview-before-commit (POST writes immediately); no seed input field on the form; no refactor of `_random_player_profile()` to accept a `name` parameter. Two GLOSSARY.md domain terms added under `### Teams and players`: **Free Agents Team** and **LG-00 generation**. Tests: `teams/tests/test_player_generator.py` (pure-unit, no Django imports — `TestDrawStats`, `TestDrawPreferredRoles`, `TestAssignSlots`, `TestNoDjangoImportsLeaked`), `teams/tests/test_services.py::TestRunPlayerGeneration`, `teams/tests/test_forms.py::TestGenerateFormPerModeValidation`, and `teams/tests/test_team_list_filters_free_agents.py::TestObjectsRegularManagerMethod`.

Locked names — service `teams.services.run_player_generation`; form `teams.forms.GenerateLeagueForm`; pure module `teams/player_generator.py` with `draw_stats(rng, mean, std_dev) -> dict[str, int]` / `draw_preferred_roles(rng) -> list[str]` / `assign_slots(preferred_roles_per_player) -> dict[str, int | None]`; module-level tuples `_STAT_FIELDS` (19, order pinned above) / `_ROLE_NAMES` (5: commander, heavy, scout, medic, ammo) / `_SLOT_KEYS` (6: commander, heavy, scout_1, scout_2, medic, ammo); manager `teams.models.TeamManager` (assigned to `Team.objects`) with `Team.objects.regular()` excluding `name="Free Agents"`; helper `teams.models.get_free_agents_team() -> Team` (module-level, not a classmethod); Free Agents magic name `"Free Agents"`; constants tuple `teams.constants.TEAM_NAMES: tuple[str, ...]` (30–50 entries). Seam contract: [`.claude/worktrees/lg-00-seam-contract.md`](../../../.claude/worktrees/lg-00-seam-contract.md).

## CRE-02 tiered generation

Adds the **League spread** ramp (GLOSSARY.md — **Even** / **Tiered** / **Steep**) to the LG-00 generation seam, so a create-League run can draw each competitive **Team** from *its own* stat mean instead of drawing all N teams from one distribution. The selector itself lives on the matches side (`CreateLeagueForm.league_spread`, Advanced create form only — see the **CRE-02 league spread** subsection in [`docs/agents/matches/league-lifecycle.md`](../matches/league-lifecycle.md)); this app owns the arithmetic and the generation call. **The tier a Team was drawn from is a generation INPUT ONLY** — it is never persisted, never queried, never surfaced, so nothing here adds a model field or a migration and the League keeps exactly one ordering after generation (the measured strength rank). Seam contract: [`.claude/worktrees/cre-02-seam-contract.md`](../../../.claude/worktrees/cre-02-seam-contract.md).

**Pure module additions — `teams/player_generator.py`.** CRE-02 only **adds** to the LG-00 surface; `draw_stats` / `draw_preferred_roles` / `assign_slots` and `_STAT_FIELDS` / `_ROLE_NAMES` / `_SLOT_KEYS` are zero-diff, and the new code stays inside the frozen import allowlist so `TestNoDjangoImportsLeaked` still covers the module.

- `LEAGUE_SPREAD_DELTAS: dict[str, float] = {"even": 0.0, "tiered": 8.0, "steep": 16.0}` — exactly three keys, exactly these lowercase tokens, exactly these float values. The tokens are the same strings the form's `league_spread` `ChoiceField` accepts, so a `cleaned_data` value indexes the dict directly.
- `compute_tier_means(num_teams: int, mean: float, delta: float) -> list[float]` — the linear, **mean-preserving** tier ramp. Returns a list of length `num_teams` where entry `i` is the stat mean the `i`-th generated Team's players are drawn from, index 0 the strongest tier and index `num_teams - 1` the weakest: `tier_mean(i) = clamp(mean + delta - 2 * delta * i / (num_teams - 1), 0.0, 100.0)`. Every entry is a `float` in `[0.0, 100.0]` and the list is monotonically **non-increasing** (strictly decreasing when `delta > 0` and no clamping is in play). **Degenerate cases** — `delta == 0` **or** `num_teams < 2` — return `[float(mean)] * num_teams`, which doubles as the `n - 1` divide-by-zero guard (so `num_teams == 0` ⇒ `[]` and `num_teams == 1` ⇒ `[float(mean)]`). **PURE:** no RNG, no I/O, no Django, deterministic given its three arguments — no seeding needed to test it.

**Mean preservation and its one caveat.** The ramp is symmetric about `mean`, so the *tier vector's* average equals `mean` exactly (`compute_tier_means(8, 50, 8)` runs 58.0 → 42.0 with a 16.0 head-to-tail gap and a list mean of exactly 50.0; `compute_tier_means(8, 50, 16)` runs 66.0 → 34.0, gap 32.0, list mean exactly 50.0). That is why a spread causes **no simulated-scoring drift and no Score Calibration re-baseline**. **The clamp is applied AFTER the ramp**, so mean preservation holds only where the ramp stays inside `[0, 100]` — at `mean=95, delta=16, num_teams=8` the head flattens at `100.0` and the list mean exceeds 95; at `mean=5, delta=16, num_teams=8` the tail flattens at `0.0` and the list mean exceeds 5. In clamped parameter ranges assert **bounds and monotonicity**, never mean preservation. Note also that the ramp preserves the mean of the *tier vector*, not the empirical mean of a finite random sample of generated Players.

**Generation call — `teams/services.py::_generate_teams`.** The helper gains one **additive keyword-only** parameter appended after `player_names_pool`: `tier_means: list[float] | None = None`. The return shape is unchanged (`list[Team]`, length `num_teams`, in creation order).

- `tier_means=None` (the default) is **byte-identical to pre-CRE-02 generation** — every Player of every Team is built with `_build_player_kwargs(rng, mean, std_dev)` exactly as before, with identical RNG consumption and identical outputs for a given seeded `rng`. Even passes `None`, **not** an all-equal list, which is what makes the default path a true no-op.
- A `list[float]` of length `num_teams` makes the Team at 0-based creation index `i` draw **all** its players — bench players 7+ included — with `_build_player_kwargs(rng, tier_means[i], std_dev)`; the `mean` parameter is then unused for those draws. The index-to-team mapping is locked: `tier_means[0]` belongs to the **first** Team created and `tier_means[num_teams - 1]` to the last. Nothing else about the loop moves — name popping, `Team.objects.create`, `Player.objects.create`, `_assign_team_slots`, `team.save()` and the append to `created_teams` keep their order, so per-player RNG consumption is unchanged.
- A list whose length `!= num_teams` **raises `ValueError`** (locked message: `f"tier_means has {len(tier_means)} entries but num_teams is {num_teams}"`), guarded at the top of the function **before the loop and before any ORM write**, so a mismatch creates zero Teams and zero Players. Silent tolerance was rejected: it would let a `num_teams` / `tier_means` drift ship a mis-tiered League undetected.

`_build_player_kwargs(rng: random.Random, mean: float, std_dev: int) -> dict` has its `mean` hint widened `int` → `float` (**its only change** — the body is untouched), because `compute_tier_means` returns `list[float]` and the downstream `draw_stats(rng, mean: float, std_dev: float)` already typed `mean` as `float`; the `int` annotation was the one dishonest link. `std_dev` stays `int`. Passing an `int` where `float` is annotated is valid under the PEP 484 numeric tower, so the three existing int-mean call sites need no edit — the keyword-only default likewise keeps `run_player_generation` and the Tournament create path (`matches/tournament_services/create.py`) source-compatible, and only `matches.league_services.create_league_and_season` passes `tier_means=`.

**Determinism / scope.** `compute_tier_means` is pure and deterministic; `_generate_teams` still takes its RNG injected, and the extreme-tier draws stay in range because `draw_stats`'s existing `max(0, min(100, ...))` clamp still applies per stat. **Out of scope (deliberate):** the free-agent pool — `_generate_free_agents` is untouched and still draws at the flat `mean` (the spread is the N competitive Teams only); `_assign_team_slots` (slot assignment is tier-independent); any model field, any migration, any persisted or queryable "projected finishing order"; any re-application at the `next_season` rollover (create-time only — **LG-04 development** owns Team strength thereafter); and any simulation / Score Calibration interaction. Tests: `TestComputeTierMeans` is **appended** to the existing `teams/tests/test_player_generator.py`, and the DB-level `_generate_teams(tier_means=...)` coverage lives in the NEW `teams/tests/test_generate_teams_tiered.py` (`TestGenerateTeamsTierMeans`), which injects `rng=random.Random(42)` and asserts a direction/magnitude gap between `created_teams[0]` and `created_teams[-1]` — **the return list's creation order, never a persisted ranking** — rather than an exact point total.

Locked names — module constant `teams.player_generator.LEAGUE_SPREAD_DELTAS` (`{"even": 0.0, "tiered": 8.0, "steep": 16.0}`); pure function `teams.player_generator.compute_tier_means(num_teams, mean, delta) -> list[float]`; `teams.services._generate_teams(..., tier_means: list[float] | None = None)` (keyword-only, `ValueError` on length mismatch); widened hint `teams.services._build_player_kwargs(rng, mean: float, std_dev: int) -> dict`; test files `teams/tests/test_player_generator.py` (append `TestComputeTierMeans` only) + `teams/tests/test_generate_teams_tiered.py` (`TestGenerateTeamsTierMeans`). Pinned by the seam contract at [`.claude/worktrees/cre-02-seam-contract.md`](../../../.claude/worktrees/cre-02-seam-contract.md).

## LG-00b roster import

CSV-driven roster import: service `teams.services.run_roster_import` behind `POST /api/teams/import/`, paired with a canonical template download (`teams.services.build_roster_template_csv`, `GET /api/teams/import/template/`).

**Pure parsing module.** `teams/roster_importer.py` is the algorithmic seam — **pure Python, no Django imports, no ORM, no settings access, no I/O** (frozen import allowlist: `csv` + `io` + `dataclasses` + `typing` from stdlib only; **explicitly forbidden**: `django.*`, `teams.models`, `teams.forms`, `teams.views`, `teams.constants`, `teams.player_generator`, `matches.*`, and any I/O / `os.path` module). The "no Django imports leaked" defensive check mirrors the RES-04 / RV-03 / HX-01 / HX-02 / LG-00 precedent. The module's public surface is one function plus four dataclasses/exception:

- `parse_roster_csv(text: str) -> ParsedRoster` — single string argument, no `**kwargs`, no optional flags. Caller owns file reading + decoding; the function defensively strips a single leading `"﻿"` BOM before invoking `csv.DictReader` (belt-and-suspenders with the form's `utf-8-sig` decode). Header-level errors raise `RosterImportError` IMMEDIATELY without attempting per-row parsing; per-row coercion errors accumulate across the whole file and bundle into a single raise after the loop plus an extra in-file collision pass; on success returns `ParsedRoster` (coercion-valid + in-file-collision-free).
- `ParsedRow(row_num, team, name, role, profile, stats, preferred_roles)` — `frozen=True` dataclass. `profile` is a 5-key dict (`age, started_playing_age, total_games, home_site, height`) whose keys MUST match `Player` field names byte-for-byte so `_apply_roster`'s `Player.objects.create(**row.profile, **row.stats)` splat lands. `stats` always carries all 19 `STAT_COLUMNS` keys, defaulted to `STAT_DEFAULT` (`50`) where the cell was blank or the column absent. `preferred_roles` is 0–5 unique lowercase role names.
- `ParsedRoster(rows, by_team)` — `frozen=True` dataclass. `rows` is the flat CSV-order list (used for diagnostics + raw iteration); `by_team` is the service's primary consumption shape, a `dict[str, list[ParsedRow]]` whose insertion order matches first-appearance order of each team in the file (Python 3.7+ dict insertion-order guarantee — locked).
- `RowError(row_num: int, field: str | None, message: str)` — `frozen=True` dataclass, hashable so tests may put them in sets. `row_num` is **1-based DATA row index**: the first data row (line 2 of the file) is `row_num=1`; the header is line 1; file-level errors use `row_num=0` (the API envelope `field` is `row:<n>` / `row:<n>:<column>`). `field` is `None` only for whole-row or whole-file errors.
- `RosterImportError(Exception)` with constructor `__init__(self, errors: list[RowError])` exposing `.errors`. `_check_db_slot_collisions` raises its own `RosterImportError` for DB-level slot collisions; the API turns either list into `roster_invalid` envelope entries (`teams.api_views.roster_import_errors_to_envelope`).

**Module constants (frozen, hand-rolled locally — no import from `player_generator`).** `ROLE_NAMES = ("commander", "heavy", "scout", "medic", "ammo")`; `SLOT_LIMITS = {"commander": 1, "heavy": 1, "scout": 2, "medic": 1, "ammo": 1}`; `STAT_COLUMNS` is the 19-tuple matching `teams/player_generator.py::_STAT_FIELDS` verbatim — including the **intentional capital-O** `Offensive_synergy` so the `Player(**stats)` splat lands on the matching field — pinned by `test_stat_columns_equals_player_generator_stat_fields` (the ONE allowed `teams.player_generator` import inside the pure-unit test file); `REQUIRED_COLUMNS` is the 8-tuple `("team", "name", "role", "age", "started_playing_age", "total_games", "home_site", "height")`; `OPTIONAL_COLUMNS = ("preferred_roles", *STAT_COLUMNS)` (20 entries); `ALL_COLUMNS = (*REQUIRED_COLUMNS, *OPTIONAL_COLUMNS)` (28 entries — the declared order that drives the template-CSV header row); `PROFILE_BOUNDS = {"age": (5, 100), "started_playing_age": (3, 100), "total_games": (0, 100_000)}`; numeric constants `STAT_DEFAULT = 50`, `STAT_MIN = 0`, `STAT_MAX = 100`, `MAX_DATA_ROWS = 1000`, `NAME_MAX_LEN = 100`, `TEAM_NAME_MAX_LEN = 100`, `HOME_SITE_MAX_LEN = 100`, `HEIGHT_MAX_LEN = 20`.

**Coercion + error policy.** Per-cell rules: `team` / `name` stripped + non-empty + ≤100 chars; `role` lowercased + stripped + must be in `ROLE_NAMES` (so `"COMMANDER"` succeeds and lowercases); the three int profile fields use `int()` + `PROFILE_BOUNDS`; `home_site` / `height` stripped strings, empty allowed (becomes `""`); `preferred_roles` split on `","` + each entry stripped + lowercased + each non-empty entry in `ROLE_NAMES` + no duplicates within the cell (empty cell or column absent → `[]`); each of the 19 stat columns: cell omitted / blank / column absent → `STAT_DEFAULT`, else `int()` bounded `[STAT_MIN, STAT_MAX]`. **Header-level errors** (missing required column, unknown column, duplicate column, > `MAX_DATA_ROWS` data rows) raise `RosterImportError` IMMEDIATELY with `row_num=0` and skip per-row parsing — there is no point reading rows under a bad header. **Per-row coercion errors** accumulate across the whole file (no per-row early return) and are joined by an **in-file collision pass** that emits four hard-reject categories before the single bundled raise: duplicate `(team, name)` pair (`field="name"`), > 1 row of any non-Scout role on the same team (`field="role"`, message contains `"Too many"`, fires on the 2nd occurrence), > 2 Scouts on the same team (`field="role"`, fires on the 3rd occurrence), and slot-overflow detected by the service's DB pre-flight pass against pre-existing Teams (`_check_db_slot_collisions`, before any write — see the service section below).

**Form.** `RosterImportForm(forms.Form)` is appended to `teams/forms.py` with a single `csv_file: forms.FileField`. The form-class constant `RosterImportForm.MAX_UPLOAD_BYTES = 2 * 1024 * 1024` is the **only** byte cap (= 2 MiB exactly, comfortably > 1000 rows — row-cap enforcement is the pure module's job, not the form's). `clean_csv_file` decodes the upload with `bytes.decode("utf-8-sig")` (BOM-tolerated, belt-and-suspenders with the pure module's defensive `﻿` strip) and stores the **decoded `str`** on `cleaned_data["csv_file"]` so the service consumes text, never an `UploadedFile`. Locked error wording substrings: `"too large"` (file-too-large) and `"must be UTF-8"` (non-UTF-8) — tests substring-match both.

**Service.** `run_roster_import(csv_text, *, manager) -> RosterImportResult(created_teams, appended_teams, player_count, row_count)` runs, inside one `transaction.atomic()` block: (1) `parsed = parse_roster_csv(csv_text)`; (2) `_check_db_slot_collisions(parsed, manager=manager)` (iterates `parsed.by_team.items()`, skips teams that do not resolve, and for each existing team emits one `RowError` per DB-side slot collision before raising `RosterImportError`); (3) `created, appended, player_count = _apply_roster(parsed, manager=manager)` (per Team in CSV-encounter order; existing Teams resolve via `resolve_import_teams` — the Account's own + Unmanaged Teams only — and misses are created stamped with the importer, see [`api.md`](api.md) **Roster-import ownership fix**; a team appears in only ONE of `created` / `appended` per call; each Player is created via `Player.objects.create(team=team, name=row.name, preferred_roles=row.preferred_roles, **row.profile, **row.stats)`; slot FK is `slot_<role>` for non-Scout or first-free of `slot_scout_1` / `slot_scout_2` for Scout, set in memory before `team.save()` once per team). A `RosterImportError` propagates only after the atomic block has rolled back, so a failed import writes nothing. `build_roster_template_csv()` builds the template body via `csv.writer` (NOT manual string formatting) so the `"scout,medic"` cell on the example Scout row is auto-quoted correctly and the body terminates with `csv.writer`'s default `"\r\n"`; the API serves it raw as `text/csv` with `Content-Disposition: attachment; filename="roster_template.csv"`.

**Template CSV.** The body is frozen byte-for-byte (line 1: the 28-column header in `ALL_COLUMNS` order; lines 2–3: two example rows for a single team `"Red Phoenix"` — a Commander and a Scout with the comma-split `preferred_roles="scout,medic"` cell — so the file demonstrates the team-grouping behaviour, the comma-split `preferred_roles` quoting requirement, and a comma inside a quoted CSV cell); the test reconstructs the expected body via `csv.writer` + `io.StringIO` rather than embedding a bytestring literal.

**Role-vs-preferred-roles column distinction.** The `role` column drives **slot assignment ONLY** (the `team.slot_<role>` FK); `preferred_roles` is a SEPARATE optional column (comma-separated within the cell) that populates the `Player.preferred_roles` JSON list — **the two columns do NOT cross-influence each other**. A Commander row whose `preferred_roles` cell omits `"commander"` still fills `slot_commander`; a Scout row whose `preferred_roles` lists `"commander,heavy"` still fills `slot_scout_1` (or `slot_scout_2`). This decouples slot membership (the competitive roster) from the per-Player `stat_for_simulation` boost (which keys off `preferred_roles`).

**Free Agents rows (LFstats import).** A row whose `team` is `Free Agents` (`roster_importer.FREE_AGENTS_TEAM_NAME`, re-declared Django-free and pinned equal to `teams.models.FREE_AGENTS_TEAM_NAME` by `test_services.py`) goes to the shared free-agent pool, which is not a roster: the parser skips the `SLOT_LIMITS` overflow check for it (the duplicate `(team, name)` check still applies), `_check_db_slot_collisions` skips it, and `_apply_roster` fetches the pool with `get_free_agents_team()` (never stamped with the importer's Account) and sets no `slot_*` FK. The pool lands in `created_teams` if it did not exist before the import, otherwise in `appended_teams`. Tests: `TestInFileCollisions.test_free_agents_team_*` and `TestRunRosterImportFreeAgents`. Used by the LFstats roster (`docs/lfstats-import.md`).

**Format + capacity guarantees.** Strict exact-match headers, case-sensitive (including the capital-O `Offensive_synergy`); UTF-8 with BOM tolerated; comma-delimited only via stdlib `csv.DictReader` (no dialect detection); 1000-row data cap (pure module, file-level error on row 1001); 2 MiB byte cap (form, `MAX_UPLOAD_BYTES`). GLOSSARY.md adds the **Roster import** glossary term under `### Teams and players` (added inline during the grilling session — the LG-00b Docs agent does NOT re-add it).

**Determinism / scope.** Fully deterministic given the input file — no `random.*` calls in either the pure module or the service. The `transaction.atomic()` block in `run_roster_import` guarantees all-or-nothing semantics (pinned by `TestRunRosterImport.test_parse_error_raises_and_writes_nothing` and `test_collision_raises_and_rolls_back_earlier_teams`). **No simulation behaviour change, no `_flush_to_db` touch, no SIM-07 / SIM-08 contract interaction, no Score Calibration re-baseline, no model field change, no migration, no ADR, no new dependency** (the pure module is stdlib-only). **Out of scope (deliberate):** no preview-before-commit (POST writes immediately on success); no per-team import entry point (single global entry only); no editing `player_generator.py` (the only cross-link is the `STAT_COLUMNS == _STAT_FIELDS` equality pin); no async / Celery / progress bar (the 1000-row cap makes the import sub-second); no per-row commit (all-or-nothing); no CSV dialect detection; no multi-file upload; no clobber / overwrite mode for existing players (the import only CREATES new Players — updating an existing Player is not in scope, and `Player.unique_together = ["team", "name"]` enforces this at the DB layer as a hard backstop).
