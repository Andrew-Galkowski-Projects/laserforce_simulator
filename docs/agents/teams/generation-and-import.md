# teams: generation and roster import

`/teams/generate/` bulk generation (LG-00), League-spread tiered generation (CRE-02) and the `/teams/import/` CSV roster import (LG-00b).
Moved verbatim from `laserforce_simulator/teams/CLAUDE.md`; the app index there points here.

## LG-00 generation

Bulk player/team generation surface at `GET /teams/generate/` (URL name `generate_players`, view `teams/views.py::generate_players`, form `teams/forms.py::GenerateLeagueForm`). Two output modes selected by the form's `num_teams` dropdown: `num_teams ≥ 1` creates new **Teams** with auto-filled 6-slot rosters + optional bench when `players_per_team > 6`; `num_teams == "0"` creates a flat free-agent pool of 12–100 players on the reserved **Free Agents Team** (GLOSSARY.md — magic name `"Free Agents"`, no `is_system` field, no model change, no migration). The new entry in `teams/urls.py` is `path("generate/", views.generate_players, name="generate_players")` (no `app_name`, mirroring the existing HX-01 pattern — `reverse("generate_players")` resolves without a namespace prefix).

**Pure generation module.** `teams/player_generator.py` is the algorithmic seam — **pure Python, no Django imports, no ORM, no settings access, no I/O, no global RNG** (frozen import allowlist: `random` for `Random` type-hint only with the RNG **injected** by the caller, `typing` for annotations, optional `collections`). The "no Django imports leaked" defensive check mirrors the RES-04 / RV-03 / HX-01 / HX-02 / HX-03 / HX-04 precedent. The module's public surface is three functions:

- `draw_stats(rng: random.Random, mean: float, std_dev: float) -> dict[str, int]` — returns a dict with **exactly 19 keys** in the module-level `_STAT_FIELDS` canonical order (3 awareness + 1 decision + 5 physical + 2 team + 8 role); each value is `max(0, min(100, round(rng.gauss(mean, std_dev))))`. Draws are made in `_STAT_FIELDS` order to keep RNG consumption deterministic given a seeded `random.Random`. The module does **not** range-check `mean` / `std_dev` — that is the form's job.
- `draw_preferred_roles(rng) -> list[str]` — returns 1–3 unique role names drawn from the module-local `_ROLE_NAMES` tuple `("commander", "heavy", "scout", "medic", "ammo")` with a `70 / 20 / 10` count distribution. Implementation pin (so tests can assert RNG-consumption parity): `n = rng.choices([1, 2, 3], weights=[70, 20, 10], k=1)[0]` then `rng.sample(_ROLE_NAMES, n)`.
- `assign_slots(preferred_roles_per_player) -> dict[str, int | None]` — deterministic greedy bipartite match of the first 6 players to the 6-slot `_SLOT_KEYS` tuple `("commander", "heavy", "scout_1", "scout_2", "medic", "ammo")`. Canonical-slot-first iteration; the slot's role is the key with any trailing `"_1"` / `"_2"` stripped (so both Scout slots want `"scout"`); lowest-unassigned-player-index tie-break (pinned by `test_assign_slots_deterministic_tiebreak`); unmatched slots receive `None` and the view back-fills them with leftover players in ascending player-index order. **Pure: no `random` calls inside `assign_slots`** — the function is deterministic given its input; the RNG enters at the level above when the view shuffles player order before assembling the input.

**`_STAT_FIELDS` canonical order (frozen, 19 entries).** `player_awareness, game_awareness, resource_awareness, decision_making, positioning, stamina, speed, flexibility, adaptability, communication, teamwork, Offensive_synergy, defensive_synergy, midfield_synergy, resupply_synergy, resupply_efficiency, accuracy, survival, special_usage`. **`Offensive_synergy` is intentionally capital-O** — the existing field name on `Player` in `teams/models.py` uses that casing and the view's `Player(**stats)` splat requires the keys to match the field names byte-for-byte. The pure module hand-rolls `_ROLE_NAMES` and `_SLOT_KEYS` locally rather than importing `matches.sim_helpers.role_constants` — keeping `teams/player_generator.py` Django-free is the contract (the role-name strings happen to align with `PlayerRoundState.role` and `Player.preferred_roles` lowercase values).

**Form.** `GenerateLeagueForm` (`teams/forms.py`) has four fields: `num_teams` (`CharField` + `Select` widget, 22 choices `"0"` + `"2".."20"` + `"random_2_10"` — **`"1"` is deliberately omitted**), `players_per_team` (`CharField`; the accepted values are `"6".."9"` + `"random_team"` (team mode) and `"12".."100"` + `"random_pool"` (pool mode) and `clean()` enforces the cross-field rule — **UXP-16:** the HTML page no longer renders the 95-option superset; it renders two per-mode selects, `form.team_players_select` (`generate-players-per-team`, `TEAM_MODE_PPT_CHOICES`) and `form.pool_players_select` (`generate-players-per-pool`, `POOL_MODE_PPT_CHOICES`), both named `players_per_team`, with the inactive mode's select `disabled` + its group `hidden` (chosen server-side by `form.is_pool_mode()`, then kept in sync by a small inline script on `num_teams` change); the API binds the same single field unchanged), `mean` (`IntegerField`, `min_value=0`, `max_value=100`, `initial=50`), `std_dev` (`IntegerField`, `min_value=1`, `max_value=40`, `initial=15`). Cross-field validation in `clean()` raises `forms.ValidationError` with locked wording — `"Players per team must be 12–100 when generating a free-agent pool"` when `num_teams == "0"` paired with anything outside `{"random_pool"}` ∪ `{12..100}`, and `"Players per team must be 6–9 when generating teams"` when `num_teams != "0"` paired with anything outside `{"6", "7", "8", "9", "random_team"}`. Tests substring-match the locked copy.

**View.** `generate_players(request)` is decorated `@transaction.atomic` so the entire POST handler runs in one transaction — a mid-loop raise rolls back every Team and Player write (pinned by `test_pure_module_raises_mid_generation_rolls_back`). On `GET` → render `templates/teams/generate_players.html` with `{"form": GenerateLeagueForm()}` (status 200). On invalid `POST` → re-render the same template with the bound form and validation errors (status 200, no DB writes). On valid `POST` → resolve `random_*` markers via `random.randint(2, 10)` (`num_teams == "random_2_10"`) / `random.randint(6, 8)` (`players_per_team == "random_team"`) / `random.randint(12, 100)` (`players_per_team == "random_pool"`), build a fresh `rng = random.Random()` (production uses fresh entropy; **no seed input field on the form, deliberately out of scope**), pre-shuffle copies of `TEAM_NAMES` and `PLAYER_NAMES`, and pop from them as Teams/Players are created with the **shuffle-and-suffix collision policy** — on `Team.objects.filter(name=candidate).exists()` (or, for the free-agents branch, per-team `Player.objects.filter(team=free_agents_team, name=candidate).exists()`) the candidate gets `" #{k}"` with `k` incrementing from 2 until a free name is found; on pool exhaustion fall back to `f"{POOL[-1]} #{n}"`. ~~The POST response re-renders `generate_players_done.html` directly (no redirect, no session round-trip).~~ **UXP-16 Post/Redirect/Get:** a valid POST stashes `{"team_ids", "free_agent_count"}` in `request.session["generate_players_result"]` and **302s to `GET /teams/generate/done/`** (URL name `generate_players_done`, view `generate_players_done`), which renders `generate_players_done.html` with context `{"created_teams": list[Team], "free_agent_count": int}` (Teams re-read through `owned_queryset`, in creation order). The result page is read-only, so a browser refresh never generates again; with nothing stashed it redirects to the form.

**Regular-teams branch (`num_teams ≥ 1`).** For each Team: pop a name + collision-check; `team = Team.objects.create(name=...)`. Pop `players_per_team` player profiles via the existing `_random_player_profile()` helper (**NOT** refactored to accept a `name` parameter — the view discards the helper's `name` field and overrides it from the popped+deduped Player-pool name). Build stats with `draw_stats(rng, mean, std_dev)` and `preferred_roles` with `draw_preferred_roles(rng)`. Create each Player via `Player.objects.create(team=team, name=..., **profile_minus_name, **stats, preferred_roles=...)`. Run `assign_slots(...)` on the first 6 players' preferred_roles lists; for each `(slot_key, player_index)` entry set the matching FK on the Team (`scout_1` → `team.slot_scout_1`, etc.); for `None`-valued slot_keys, back-fill with leftover players (those whose index was never assigned) in ascending player-index order. After back-fill, all 6 slots are filled. Players 7+ (`players_per_team > 6`) are bench: created on the Team but never assigned to a `slot_*` FK. `team.save()` once after all slot FKs are set.

**Free-agents branch (`num_teams == "0"`).** `free_agents = get_free_agents_team()`. Pop `players_per_team` player profiles (with per-team name collision-check against `free_agents`). For each, `Player.objects.create(team=free_agents, ...)` with stats and preferred_roles as above. **Do NOT touch any `slot_*` FK on the Free Agents Team** — it stays an unfilled roster on purpose (`is_valid_roster` returns False, by design — the Free Agents Team is a player container, not a competitive roster).

Idempotent across runs — the second call returns the same `pk`. ## CRE-02 tiered generation

Adds the **League spread** ramp (GLOSSARY.md — **Even** / **Tiered** / **Steep**) to the LG-00 generation seam, so a create-League run can draw each competitive **Team** from *its own* stat mean instead of drawing all N teams from one distribution. The selector itself lives on the matches side (`CreateLeagueForm.league_spread`, Advanced create form only — see the **CRE-02 league spread** subsection in [`docs/agents/matches/league-lifecycle.md`](../matches/league-lifecycle.md)); this app owns the arithmetic and the generation call. **The tier a Team was drawn from is a generation INPUT ONLY** — it is never persisted, never queried, never surfaced, so nothing here adds a model field or a migration and the League keeps exactly one ordering after generation (the measured strength rank). Seam contract: [`.claude/worktrees/cre-02-seam-contract.md`](../../../.claude/worktrees/cre-02-seam-contract.md).

**Pure module additions — `teams/player_generator.py`.** CRE-02 only **adds** to the LG-00 surface; `draw_stats` / `draw_preferred_roles` / `assign_slots` and `_STAT_FIELDS` / `_ROLE_NAMES` / `_SLOT_KEYS` are zero-diff, and the new code stays inside the frozen import allowlist so `TestNoDjangoImportsLeaked` still covers the module.

- `LEAGUE_SPREAD_DELTAS: dict[str, float] = {"even": 0.0, "tiered": 8.0, "steep": 16.0}` — exactly three keys, exactly these lowercase tokens, exactly these float values. The tokens are the same strings the form's `league_spread` `ChoiceField` accepts, so a `cleaned_data` value indexes the dict directly.
- `compute_tier_means(num_teams: int, mean: float, delta: float) -> list[float]` — the linear, **mean-preserving** tier ramp. Returns a list of length `num_teams` where entry `i` is the stat mean the `i`-th generated Team's players are drawn from, index 0 the strongest tier and index `num_teams - 1` the weakest: `tier_mean(i) = clamp(mean + delta - 2 * delta * i / (num_teams - 1), 0.0, 100.0)`. Every entry is a `float` in `[0.0, 100.0]` and the list is monotonically **non-increasing** (strictly decreasing when `delta > 0` and no clamping is in play). **Degenerate cases** — `delta == 0` **or** `num_teams < 2` — return `[float(mean)] * num_teams`, which doubles as the `n - 1` divide-by-zero guard (so `num_teams == 0` ⇒ `[]` and `num_teams == 1` ⇒ `[float(mean)]`). **PURE:** no RNG, no I/O, no Django, deterministic given its three arguments — no seeding needed to test it.

**Mean preservation and its one caveat.** The ramp is symmetric about `mean`, so the *tier vector's* average equals `mean` exactly (`compute_tier_means(8, 50, 8)` runs 58.0 → 42.0 with a 16.0 head-to-tail gap and a list mean of exactly 50.0; `compute_tier_means(8, 50, 16)` runs 66.0 → 34.0, gap 32.0, list mean exactly 50.0). That is why a spread causes **no simulated-scoring drift and no Score Calibration re-baseline**. **The clamp is applied AFTER the ramp**, so mean preservation holds only where the ramp stays inside `[0, 100]` — at `mean=95, delta=16, num_teams=8` the head flattens at `100.0` and the list mean exceeds 95; at `mean=5, delta=16, num_teams=8` the tail flattens at `0.0` and the list mean exceeds 5. In clamped parameter ranges assert **bounds and monotonicity**, never mean preservation. Note also that the ramp preserves the mean of the *tier vector*, not the empirical mean of a finite random sample of generated Players.

**Generation call — `teams/views.py::_generate_teams`.** The helper gains one **additive keyword-only** parameter appended last, after `player_names_pool`: `tier_means: list[float] | None = None`. The return shape is unchanged (`list[Team]`, length `num_teams`, in creation order).

- `tier_means=None` (the default) is **byte-identical to pre-CRE-02 generation** — every Player of every Team is built with `_build_player_kwargs(rng, mean, std_dev)` exactly as before, with identical RNG consumption and identical outputs for a given seeded `rng`. Even passes `None`, **not** an all-equal list, which is what makes the default path a true no-op.
- A `list[float]` of length `num_teams` makes the Team at 0-based creation index `i` draw **all** its players — bench players 7+ included — with `_build_player_kwargs(rng, tier_means[i], std_dev)`; the `mean` parameter is then unused for those draws. The index-to-team mapping is locked: `tier_means[0]` belongs to the **first** Team created and `tier_means[num_teams - 1]` to the last. Nothing else about the loop moves — name popping, `Team.objects.create`, `Player.objects.create`, `_assign_team_slots`, `team.save()` and the append to `created_teams` keep their order, so per-player RNG consumption is unchanged.
- A list whose length `!= num_teams` **raises `ValueError`** (locked message: `f"tier_means has {len(tier_means)} entries but num_teams is {num_teams}"`), guarded at the top of the function **before the loop and before any ORM write**, so a mismatch creates zero Teams and zero Players. Silent tolerance was rejected: it would let a `num_teams` / `tier_means` drift ship a mis-tiered League undetected.

`_build_player_kwargs(rng: random.Random, mean: float, std_dev: int) -> dict` has its `mean` hint widened `int` → `float` (**its only change** — the body is untouched), because `compute_tier_means` returns `list[float]` and the downstream `draw_stats(rng, mean: float, std_dev: float)` already typed `mean` as `float`; the `int` annotation was the one dishonest link. `std_dev` stays `int`. Passing an `int` where `float` is annotated is valid under the PEP 484 numeric tower, so the three existing int-mean call sites need no edit — the keyword-only default likewise keeps `generate_players` and the Tournament create path (`matches/tournament_services/create.py` since ANG-01f) source-compatible, and only `matches.league_views._create_league_and_season` passes `tier_means=`.

**Determinism / scope.** `compute_tier_means` is pure and deterministic; `_generate_teams` still takes its RNG injected, and the extreme-tier draws stay in range because `draw_stats`'s existing `max(0, min(100, ...))` clamp still applies per stat. **Out of scope (deliberate):** the free-agent pool — `_generate_free_agents` is untouched and still draws at the flat `mean` (the spread is the N competitive Teams only); `_assign_team_slots` (slot assignment is tier-independent); any model field, any migration, any persisted or queryable "projected finishing order"; any re-application at the `next_season` rollover (create-time only — **LG-04 development** owns Team strength thereafter); and any simulation / Score Calibration interaction. Tests: `TestComputeTierMeans` is **appended** to the existing `teams/tests/test_player_generator.py`, and the DB-level `_generate_teams(tier_means=...)` coverage lives in the NEW `teams/tests/test_generate_teams_tiered.py` (`TestGenerateTeamsTierMeans`), which injects `rng=random.Random(42)` and asserts a direction/magnitude gap between `created_teams[0]` and `created_teams[-1]` — **the return list's creation order, never a persisted ranking** — rather than an exact point total.

Locked names — module constant `teams.player_generator.LEAGUE_SPREAD_DELTAS` (`{"even": 0.0, "tiered": 8.0, "steep": 16.0}`); pure function `teams.player_generator.compute_tier_means(num_teams, mean, delta) -> list[float]`; `teams.views._generate_teams(..., tier_means: list[float] | None = None)` (keyword-only, appended last, `ValueError` on length mismatch); widened hint `teams.views._build_player_kwargs(rng, mean: float, std_dev: int) -> dict`; test files `teams/tests/test_player_generator.py` (append `TestComputeTierMeans` only) + `teams/tests/test_generate_teams_tiered.py` (`TestGenerateTeamsTierMeans`). Pinned by the seam contract at [`.claude/worktrees/cre-02-seam-contract.md`](../../../.claude/worktrees/cre-02-seam-contract.md).

## LG-00b roster import

CSV-driven roster-import surface at `GET/POST /teams/import/` (URL name `import_roster`, view `teams/views.py::import_roster`) paired with a canonical template download at `GET /teams/import/template.csv` (URL name `import_roster_template`, view `teams/views.py::import_roster_template`). Both `path(...)` entries are appended to `teams/urls.py` **above** the existing `<int:team_id>/` capture-group routes so the literal `import/` segment is unambiguous. Tests reverse via `reverse("import_roster")` and `reverse("import_roster_template")` — no `app_name:` prefix (consistent with the existing `teams/urls.py` pattern). Entry point is a single `"Import Roster"` anchor (DOM id `roster-import-link`) added to `templates/teams/team_list.html` between the LG-00 `generate-players-link` and the existing `Create New Team` button.

**Pure parsing module.** `teams/roster_importer.py` is the algorithmic seam — **pure Python, no Django imports, no ORM, no settings access, no I/O** (frozen import allowlist: `csv` + `io` + `dataclasses` + `typing` from stdlib only; **explicitly forbidden**: `django.*`, `teams.models`, `teams.forms`, `teams.views`, `teams.constants`, `teams.player_generator`, `matches.*`, and any I/O / `os.path` module). The "no Django imports leaked" defensive check mirrors the RES-04 / RV-03 / HX-01 / HX-02 / LG-00 precedent. The module's public surface is one function plus four dataclasses/exception:

- `parse_roster_csv(text: str) -> ParsedRoster` — single string argument, no `**kwargs`, no optional flags. Caller owns file reading + decoding; the function defensively strips a single leading `"﻿"` BOM before invoking `csv.DictReader` (belt-and-suspenders with the form's `utf-8-sig` decode). Header-level errors raise `RosterImportError` IMMEDIATELY without attempting per-row parsing; per-row coercion errors accumulate across the whole file and bundle into a single raise after the loop plus an extra in-file collision pass; on success returns `ParsedRoster` (coercion-valid + in-file-collision-free).
- `ParsedRow(row_num, team, name, role, profile, stats, preferred_roles)` — `frozen=True` dataclass. `profile` is a 5-key dict (`age, started_playing_age, total_games, home_site, height`) whose keys MUST match `Player` field names byte-for-byte so the view's `Player.objects.create(**row.profile, **row.stats)` splat lands. `stats` always carries all 19 `STAT_COLUMNS` keys, defaulted to `STAT_DEFAULT` (`50`) where the cell was blank or the column absent. `preferred_roles` is 0–5 unique lowercase role names.
- `ParsedRoster(rows, by_team)` — `frozen=True` dataclass. `rows` is the flat CSV-order list (used for diagnostics + raw iteration); `by_team` is the view's primary consumption shape, a `dict[str, list[ParsedRow]]` whose insertion order matches first-appearance order of each team in the file (Python 3.7+ dict insertion-order guarantee — locked).
- `RowError(row_num: int, field: str | None, message: str)` — `frozen=True` dataclass, hashable so tests may put them in sets. `row_num` is **1-based DATA row index**: the first data row (line 2 of the file) is `row_num=1`; the header is line 1; file-level errors use `row_num=0` so the template sorts errors top-to-bottom with file-level first. `field` is `None` only for whole-row or whole-file errors.
- `RosterImportError(Exception)` with constructor `__init__(self, errors: list[RowError])` exposing `.errors`. The view re-renders this list verbatim and may **extend** it with DB-level slot collisions detected during the pre-flight check before re-raising.

**Module constants (frozen, hand-rolled locally — no import from `player_generator`).** `ROLE_NAMES = ("commander", "heavy", "scout", "medic", "ammo")`; `SLOT_LIMITS = {"commander": 1, "heavy": 1, "scout": 2, "medic": 1, "ammo": 1}`; `STAT_COLUMNS` is the 19-tuple matching `teams/player_generator.py::_STAT_FIELDS` verbatim — including the **intentional capital-O** `Offensive_synergy` so the view's `Player(**stats)` splat lands on the matching field — pinned by `test_stat_columns_equals_player_generator_stat_fields` (the ONE allowed `teams.player_generator` import inside the pure-unit test file); `REQUIRED_COLUMNS` is the 8-tuple `("team", "name", "role", "age", "started_playing_age", "total_games", "home_site", "height")`; `OPTIONAL_COLUMNS = ("preferred_roles", *STAT_COLUMNS)` (20 entries); `ALL_COLUMNS = (*REQUIRED_COLUMNS, *OPTIONAL_COLUMNS)` (28 entries — the declared order that drives the template-CSV header row); `PROFILE_BOUNDS = {"age": (5, 100), "started_playing_age": (3, 100), "total_games": (0, 100_000)}`; numeric constants `STAT_DEFAULT = 50`, `STAT_MIN = 0`, `STAT_MAX = 100`, `MAX_DATA_ROWS = 1000`, `NAME_MAX_LEN = 100`, `TEAM_NAME_MAX_LEN = 100`, `HOME_SITE_MAX_LEN = 100`, `HEIGHT_MAX_LEN = 20`.

**Coercion + error policy.** Per-cell rules: `team` / `name` stripped + non-empty + ≤100 chars; `role` lowercased + stripped + must be in `ROLE_NAMES` (so `"COMMANDER"` succeeds and lowercases); the three int profile fields use `int()` + `PROFILE_BOUNDS`; `home_site` / `height` stripped strings, empty allowed (becomes `""`); `preferred_roles` split on `","` + each entry stripped + lowercased + each non-empty entry in `ROLE_NAMES` + no duplicates within the cell (empty cell or column absent → `[]`); each of the 19 stat columns: cell omitted / blank / column absent → `STAT_DEFAULT`, else `int()` bounded `[STAT_MIN, STAT_MAX]`. **Header-level errors** (missing required column, unknown column, duplicate column, > `MAX_DATA_ROWS` data rows) raise `RosterImportError` IMMEDIATELY with `row_num=0` and skip per-row parsing — there is no point reading rows under a bad header. **Per-row coercion errors** accumulate across the whole file (no per-row early return) and are joined by an **in-file collision pass** that emits four hard-reject categories before the single bundled raise: duplicate `(team, name)` pair (`field="name"`), > 1 row of any non-Scout role on the same team (`field="role"`, message contains `"Too many"`, fires on the 2nd occurrence), > 2 Scouts on the same team (`field="role"`, fires on the 3rd occurrence), and slot-overflow detected by the view's DB pre-flight pass against pre-existing Teams (appended to the same `RosterImportError.errors` before any write — see view section below).

**Form.** `RosterImportForm(forms.Form)` is appended to `teams/forms.py` with a single `csv_file: forms.FileField` (widget id `roster-import-file`, `accept=".csv,text/csv"`). The form-class constant `RosterImportForm.MAX_UPLOAD_BYTES = 2 * 1024 * 1024` is the **only** byte cap (= 2 MiB exactly, comfortably > 1000 rows — row-cap enforcement is the pure module's job, not the form's). `clean_csv_file` decodes the upload with `bytes.decode("utf-8-sig")` (BOM-tolerated, belt-and-suspenders with the pure module's defensive `﻿` strip) and stores the **decoded `str`** on `cleaned_data["csv_file"]` so the view consumes text, never an `UploadedFile`. Locked error wording substrings: `"too large"` (file-too-large) and `"must be UTF-8"` (non-UTF-8) — tests substring-match both.

**View.** `import_roster(request)` is decorated `@transaction.atomic` so the entire POST handler runs in one transaction. The catch block uses **explicit `transaction.set_rollback(True)`** before re-rendering the form page — mandatory because the view returns a 200 response after catching `RosterImportError`, which without the explicit rollback would NOT trigger `@transaction.atomic`'s automatic rollback on raise; pinned by `test_db_slot_collision_rolls_back_all_writes`. On GET → render `templates/teams/roster_import.html` with `{"form": RosterImportForm(), "errors": [], "row_errors": []}` (status 200). On invalid form POST → re-render with the bound form (status 200, no DB writes). On valid POST, in order: (1) `parsed = parse_roster_csv(form.cleaned_data["csv_file"])`; (2) `_check_db_slot_collisions(parsed)` (its name is pinned for test monkey-patching stability — iterates `parsed.by_team.items()`, skips teams that do not exist, and for each existing team emits one `RowError` per DB-side slot collision before re-raising `RosterImportError`); (3) `created, appended, player_count = _apply_roster(parsed)` (also pinned — per Team in CSV-encounter order, `Team.objects.get_or_create(name=team_name)` auto-creates missing Teams while existing Teams are appended to — **superseded by ANG-01a:** both helpers now live in `teams/services.py` (re-exported from `teams.views`), take a required keyword `manager`, resolve existing Teams via `resolve_import_teams` (the Account's own + Unmanaged Teams only) and create misses stamped with the importer — no more `get_or_create`; the whole sequence is wrapped by `run_roster_import`, see **REST API → Roster-import ownership fix** above; a team appears in only ONE of `created` / `appended` per call; each Player is created via `Player.objects.create(team=team, name=row.name, preferred_roles=row.preferred_roles, **row.profile, **row.stats)`; slot FK is `slot_<role>` for non-Scout or first-free of `slot_scout_1` / `slot_scout_2` for Scout, set in memory before `team.save()` once per team); (4) render `templates/teams/roster_import_done.html` with context `{"created_teams": list[Team], "appended_teams": list[Team], "player_count": int, "row_count": int}` (status 200, no redirect, no session round-trip). **Role-vs-preferred-roles column distinction.** The `role` column drives **slot assignment ONLY** (the `team.slot_<role>` FK); `preferred_roles` is a SEPARATE optional column (comma-separated within the cell) that populates the `Player.preferred_roles` JSON list — **the two columns do NOT cross-influence each other**. This decouples slot membership (the competitive roster) from the per-Player `stat_for_simulation` boost (which keys off `preferred_roles`).
