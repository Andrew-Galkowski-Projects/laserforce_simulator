# teams: players tab

The sortable, paginated `/players/` index (LG-00c).
Moved verbatim from `laserforce_simulator/teams/CLAUDE.md`; the app index there points here.

## LG-00c sortable players tab

Read-only, server-side-sort, paginated index of every Player (including the Free Agents pool — no special-case exclusion) at `GET /players/` (URL name `player_list`, view `teams/views.py::player_list`, template `templates/teams/player_list.html`). Three query params drive presentation: `?sort=<key>` (default `"team"`, 23 accepted keys), `?dir=<asc|desc>` (default `"asc"`, case-sensitive — `"ASC"` falls back to `"asc"`), and `?page=<int>` (default 1, `EmptyPage` / `PageNotAnInteger` → page 1). Invalid params never raise — every bad input is coerced to a default by the two forgiving-fallback helpers (HX-02 pattern), and `get_object_or_404` is not used (the view never 404s).

**URL include.** One new `path("", views.player_list, name="player_list")` is appended to `teams/player_urls.py` **after** the two existing entries — final order is `benchmarks/` → `<int:player_id>/stats/` → `""`. The trailing position is mandatory: the `<int:player_id>` capture group cannot match an empty path segment, but the explicit ordering pin prevents a future regex change from silently shadowing the new route. Reverse via the bare `reverse("player_list")` — no `app_name:` prefix, consistent with the existing HX-01 / HX-02 routes in the same file. The outer `path("players/", include("teams.player_urls"))` mount in `laserforce_simulator/urls.py` is reused unchanged.

**No new pure-aggregation module.** LG-00c **deliberately ships no `teams/*.py` aggregation seam** — the helpers and constants live inline at module scope in `teams/views.py`, contrasting with HX-01 (`teams/career_stats.py`), HX-02 (`teams/role_benchmarks.py`), LG-00 (`teams/player_generator.py`), and LG-00b (`teams/roster_importer.py`) which all ship a pure module. The test file imports `_coerce_sort`, `_coerce_dir`, `_SORT_KEYS`, `_SORT_KEYS_DISPLAY`, `_VALID_DIRS`, and `_PAGE_SIZE` directly from `teams.views`. The helper unit tests (`TestCoerceSortAndDir`) run under Django's `TestCase` runner because of the `teams.views` import — they are NOT pure-unit in the HX-01 / HX-02 sense (those have actual Django-free pure modules with `test_no_django_imports_leaked` defensive checks; LG-00c does not).

**Sort whitelist — 23 accepted keys total.** Four new module-level constants in `teams/views.py`, placed beside the existing HX-02 `_coerce_threshold` / `_coerce_display`. `_SORT_KEYS: dict[str, str]` is a **22-entry** dict literal (URL key → ORM target) — the 19 stat fields plus `name` / `team` / `overall_rating`; insertion order is declared order for clarity, tests treat membership not ordering. `_SORT_KEYS_DISPLAY: tuple[tuple[str, str], ...]` is the **23-entry** display tuple (the 22 ORM-backed keys PLUS the `preferred_roles` sentinel — that's how the template iterates the column order including the JSON-field column) in the locked display order `(name, team, preferred_roles, overall_rating, player_awareness, game_awareness, resource_awareness, decision_making, positioning, stamina, speed, flexibility, adaptability, communication, teamwork, offensive_synergy, defensive_synergy, midfield_synergy, resupply_synergy, resupply_efficiency, accuracy, survival, special_usage)` paired with human labels `(Name, Team, Preferred Roles, Overall, Player Aware, Game Aware, Resource Aware, Decision, Positioning, Stamina, Speed, Flexibility, Adaptability, Communication, Teamwork, Offensive Syn, Defensive Syn, Midfield Syn, Resupply Syn, Resupply Eff, Accuracy, Survival, Special Usage)`. `_VALID_DIRS = ("asc", "desc")` and `_PAGE_SIZE = 50` round out the constants.

**Capital-O `Offensive_synergy` casing quirk.** URL key `offensive_synergy` (lowercase alias) maps to ORM target `Offensive_synergy` (capital-O, matching the existing `Player.Offensive_synergy` field byte-for-byte and the `_STAT_FIELDS` / `STAT_COLUMNS` precedent set by LG-00 / LG-00b). Pinned by `test_sort_by_offensive_synergy_url_alias_maps_to_capital_O_field` — the test creates 3 Players with distinct `Offensive_synergy` values, GETs `?sort=offensive_synergy&dir=desc` with the lowercase URL key, and asserts the top row is the highest-value player.

**`preferred_roles` Python-side sentinel — the 23rd accepted key.** `"preferred_roles"` is NOT in `_SORT_KEYS` (the field is a JSON list with no ORM target). The view handles it in a separate branch: materialise via `rows = list(qs)`, then `rows.sort(key=lambda p: (",".join(p.preferred_roles or []), p.name), reverse=(direction == "desc"))`, then `Paginator(rows, _PAGE_SIZE)`. Empty `preferred_roles` joins to `""` which sorts to the **TOP** of asc (`""` is lexicographically less than any non-empty string); the secondary `player.name` component is the deterministic tiebreak. Pinned by `test_sort_by_preferred_roles_python_branch` — the test creates 3 Players with `preferred_roles` = `[]`, `["scout"]`, `["commander", "heavy"]` and GETs `?sort=preferred_roles&dir=asc`, asserting the empty-list player sorts first, then `"commander,heavy"`, then `"scout"`.

**Forgiving-fallback helpers (inline, mirror HX-02).** Two new module-level functions at the same scope as `_coerce_threshold` / `_coerce_display`. `_coerce_sort(raw: str | None, default: str = "team") -> str` returns `raw` if `raw in _SORT_KEYS or raw == "preferred_roles"`, else `default` — the accepted-key set is the union of `_SORT_KEYS` keys and the `preferred_roles` sentinel (inlined, not exposed as a module-level constant). `_coerce_dir(raw: str | None, default: str = "asc") -> str` returns `raw` if `raw in _VALID_DIRS`, else `default` — case-sensitive (so `"ASC"` falls back to `"asc"`, mirroring `_coerce_display`'s casing discipline). Both helpers return `str` (never `None`); tests pin direct-call behaviour (`TestCoerceSortAndDir`).

**View.** `player_list(request)` is undecorated, runs `_coerce_sort(request.GET.get("sort"))` and `_coerce_dir(request.GET.get("dir"))`, builds the queryset via `Player.objects.select_related("team").annotate(overall_rating_db=...)` where the annotation is `(sum of 19 F-fields) / 19.0` (using `F("Offensive_synergy")` with the capital-O to match the field; the `/ 19.0` ensures float semantics under the SQL backend). The ORM branch then runs `qs.order_by(prefix + _SORT_KEYS[sort], "name")` where `prefix = "" if direction == "asc" else "-"` — the secondary `"name"` tiebreak is appended unconditionally (even when sorting by name itself — harmless, keeps the branch uniform). The Python branch (`sort == "preferred_roles"`) materialises and sorts in memory as described above. `Paginator(qs_or_rows, _PAGE_SIZE)` handles pagination; `EmptyPage` / `PageNotAnInteger` fall back to page 1. The view assembles two URL-encoded helper strings via `request.GET.copy()` + `.pop()`: `querystring_without_page` (used by Previous / Next page links so sort + dir survive page navigation) and `querystring_without_sort_dir_page` (used by column-header `<a>` hrefs so clicking a header drops `page=` and resets to page 1). Context ships **exactly seven** frozen keys: `page_obj, paginator, sort, dir, sort_keys, querystring_without_page, querystring_without_sort_dir_page`. The ORM branch issues exactly one queryset materialisation (the `Paginator` `.count()` + `.page()` round-trips are part of the paginator contract); the Python branch materialises once via `list(qs)`. Imports added: `from django.db.models import F` and `from django.core.paginator import Paginator, EmptyPage, PageNotAnInteger` (any subset already present is reused).

**Template surface.** NEW `templates/teams/player_list.html` extends `base.html` with `{% block title %}Players{% endblock %}` and renders a `<div class="table-responsive">` wrapper (Bootstrap 5.3, already on `base.html`) around a single `<table id="player-list-table">`. The `<thead>` iterates `sort_keys` (the 23-entry `_SORT_KEYS_DISPLAY`) emitting one `<th id="player-list-th-{url_key}">` per column with an `<a href>` that flips direction on the active column (`asc` ↔ `desc`) and starts new columns at `asc`; the href is built from `querystring_without_sort_dir_page` plus `sort=<key>&dir=<next-dir>` so clicking any header drops `page=`. **Active-column arrow glyphs** are the locked Unicode `↑` (U+2191, asc) and `↓` (U+2193, desc), appended to the human label with a single space (`{{ label }} ↑` / `{{ label }} ↓`) — pinned by `test_active_column_renders_arrow_glyph` via direct substring presence. The `<tbody>` renders one row per Player on the page: the `name` cell is `<a href="{% url 'player_career_stats' player.id %}">{{ player.name }}</a>` (HX-01 career-page link, pinned by `test_name_cell_links_to_career_stats`); the `team` cell is `<a href="{% url 'team_detail' player.team.id %}">{{ player.team.name }}</a>` (pinned by `test_team_cell_links_to_team_detail` — Free Agents Team players link to their own team detail page, no special-case, pinned by `test_free_agents_players_appear_in_listing`); the `preferred_roles` cell is `{{ player.preferred_roles|join:", " }}` (empty list renders an empty cell); the `overall_rating` cell uses the `@property` (NOT the annotation) via `{{ player.overall_rating|floatformat:1 }}` for consistency with the rest of the codebase; and the 19 stat cells render plain integers including the capital-O `{{ player.Offensive_synergy }}` attribute. The pagination block is a `<nav id="player-list-pagination">` rendered only when `page_obj.has_other_pages` is true, with Previous / Page X of Y / Next links whose hrefs use `querystring_without_page` so sort + dir are preserved across page navigation (pinned by `test_pagination_carries_sort_and_dir_in_links`); the column-header hrefs use `querystring_without_sort_dir_page` so clicking a header drops `page=` (pinned by `test_sort_change_resets_to_page_1`). The pagination test creates 51 Players so page 1 has 50 rows and page 2 has 1 row.

**`base.html` nav link.** Exactly **one new line** is added to `templates/base.html`: `<a class="nav-link" id="player-list-nav-link" href="{% url 'player_list' %}">Players</a>` placed in the existing `<div class="navbar-nav ms-auto">` block immediately AFTER the existing `Teams` `<a>` and BEFORE the existing `Matches` `<a>`. The new anchor uses `class="nav-link"` (same as siblings) — no CSS class change, no reordering of other nav links. Pinned by `test_nav_link_present_in_base_html` — the test GETs any view that extends `base.html` (the contract picks `team_list`), then asserts both substrings `"Players"` and `id="player-list-nav-link"` appear in the response body.

**Tests.** Live in **one NEW file** `teams/tests/test_player_list_view.py` with two classes and **27 tests total**. `TestCoerceSortAndDir` (10 helper tests — `test_coerce_sort_accepts_every_orm_key`, `test_coerce_sort_accepts_preferred_roles_sentinel`, `test_coerce_sort_falls_back_on_unknown_value`, `test_coerce_sort_falls_back_on_none`, `test_coerce_sort_falls_back_on_empty_string`, `test_coerce_dir_accepts_asc`, `test_coerce_dir_accepts_desc`, `test_coerce_dir_falls_back_on_unknown`, `test_coerce_dir_falls_back_on_none`, `test_coerce_dir_falls_back_on_uppercase`) — these import `_coerce_sort` / `_coerce_dir` / `_SORT_KEYS` / `_VALID_DIRS` directly from `teams.views` and run under Django's `TestCase` runner (they don't strictly need a DB, but the file inherits the Django test runner because of the `teams.views` import). `TestPlayerListView` (17 Django `TestCase` view tests via `reverse("player_list")` + the test client, real ORM, no mocks — `test_get_returns_200_with_default_sort`, `test_default_sort_is_team_asc_with_name_secondary` (pins the `Alpha/Aaron, Alpha/Zed, Bravo/Aaron, Bravo/Zed` row order), `test_sort_by_name_asc`, `test_sort_by_overall_rating_desc`, `test_sort_by_offensive_synergy_url_alias_maps_to_capital_O_field`, `test_sort_by_preferred_roles_python_branch`, `test_sort_by_every_stat_key_returns_200` (parametrised loop over every `(url_key, _)` in `_SORT_KEYS_DISPLAY` for both directions), `test_invalid_sort_falls_back_to_team`, `test_invalid_dir_falls_back_to_asc`, `test_pagination_renders_50_per_page` (51 Players, 50 on page 1, 1 on page 2), `test_pagination_carries_sort_and_dir_in_links`, `test_sort_change_resets_to_page_1`, `test_free_agents_players_appear_in_listing` (via `get_free_agents_team()`), `test_name_cell_links_to_career_stats`, `test_team_cell_links_to_team_detail`, `test_active_column_renders_arrow_glyph` (asserts `Name ↑` for `?sort=name&dir=asc` and `Name ↓` for `?sort=name&dir=desc`), `test_nav_link_present_in_base_html`).

**Per-page selector (`?per_page=` extension landed in-PR).** `?per_page=10|25|50|100` (default `10`) — the original seam contract was scope-out for `per_page` but the feature was added in the same PR as a user-requested follow-up. New module-level constants in `teams/views.py`: `_VALID_PAGE_SIZES: tuple[int, ...] = (10, 25, 50, 100)` and `_DEFAULT_PAGE_SIZE: int = 10` (the previous `_PAGE_SIZE = 50` constant is REMOVED — the page size is dynamic now). New helper `_coerce_per_page(raw: str | None, default: int = _DEFAULT_PAGE_SIZE) -> int` mirrors HX-02's `_coerce_threshold` truthy-int coerce discipline: parses via `int()`; on `TypeError` / `ValueError` / missing returns default; on numeric-but-out-of-whitelist (`0`, negatives, `37`, `9999`, `11`, `49`, `101`) returns default. The view reads `per_page = _coerce_per_page(request.GET.get("per_page"))` and passes it to BOTH `Paginator(...)` calls; both querystring helpers carry the coerced `per_page` value via `qs["per_page"] = str(per_page)` so it survives across page navigation AND across column-header re-sorts. The context dict gains **two new keys** — `per_page` (the coerced int) and `page_size_options` (the `_VALID_PAGE_SIZES` tuple, iterated by the template `<select>`) — bringing the total to **9** (was 7 pre-extension). The dropdown surface is a small `<form method="get" id="player-list-per-page-form" class="mb-3">` placed above the table containing `<input type="hidden" name="sort" value="{{ sort }}">` + `<input type="hidden" name="dir" value="{{ dir }}">` (so changing the page size does NOT reset the user's column ordering) + a `<label for="player-list-per-page-select">Show:</label>` + `<select name="per_page" id="player-list-per-page-select" onchange="this.form.submit()">` (auto-submit on change, mirrors HX-02's submit-button form pattern but with a single-control auto-submit UX) with one `<option value="{size}" {% if size == per_page %}selected{% endif %}>{size}</option>` per `_VALID_PAGE_SIZES` entry + a `<noscript><button type="submit">Apply</button></noscript>` fallback for JS-disabled clients. New DOM ids: `player-list-per-page-form` + `player-list-per-page-select`. Tests cover: `_coerce_per_page` accepts every whitelisted size (`TestCoerceSortAndDir.test_coerce_per_page_accepts_every_whitelisted_size`); falls back on `None` / empty / non-int / out-of-whitelist (`test_coerce_per_page_falls_back_on_none` + `_falls_back_on_empty_string` + `_falls_back_on_non_int` + `_falls_back_on_out_of_whitelist`); view renders default 10 on missing param (`test_default_pagination_is_10_per_page` — was `test_pagination_renders_50_per_page` pre-extension); every valid `?per_page=` value renders the expected row count (`test_per_page_25_50_100_each_render`); invalid values silently coerce to default (`test_invalid_per_page_falls_back_to_default`); dropdown marks exactly one `<option selected>` and exposes locked DOM ids (`test_per_page_select_marks_active_option`); pagination links carry `per_page=` across pages (`test_pagination_carries_sort_and_dir_in_links` + `test_pagination_carries_per_page_in_links`); column-header re-sort hrefs carry `per_page=` (the `test_sort_change_resets_to_page_1` assertion now checks `per_page=10` is in the column-header qs but `&page=` is not — the substring check uses `qs.startswith("page=") or "&page=" in qs` to avoid matching the literal `page=` substring inside `per_page=`).

**Inline fixes landed in the same PR.** Three additional inline fixes were made during the web smoke / responsive smoke after the initial parallel-agents land — captured in `issues.md` as **LG00c-7** (pagination Previous/Next hrefs were carrying uncoerced invalid `?sort=&dir=` values verbatim; fixed by assigning the COERCED values back into the `QueryDict` before `.urlencode()` so the rendered URL always reflects the canonical/coerced query; regression test `test_pagination_links_drop_invalid_sort_and_dir`), **LG00c-8** (at viewports ≥ 1320px the 23-column table was clamped to Bootstrap's `.container.mt-4` max-width PLUS a redundant inner `<div class="container mt-4">` in the template, wasting up to ~600px of viewport on a 1920px screen; fixed by dropping the redundant inner `.container` and applying `style="margin-left: calc(-50vw + 50%); margin-right: calc(-50vw + 50%); padding: 0 1rem;"` to the `.table-responsive` wrapper — the calc no-ops at small viewports, breaks the wrapper out of the outer container to span the full viewport at wide ones; verified at 720 / 800 / 1280 / 1920 / 2560px with zero wasted space at every size), and **LG00c-9** (a multi-line `{# ... #}` block was rendering literally as visible text — Django `{# #}` is single-line only; collapsed to a one-line `{# #}` comment).
