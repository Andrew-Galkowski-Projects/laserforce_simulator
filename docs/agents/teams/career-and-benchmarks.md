# teams: career stats and role benchmarks

The career stats (HX-01), its 12-stat benchmark extension (HX-01b) and the Role benchmarks (HX-02): SPA screens `/players/:id/stats` and `/players/benchmarks` over `GET /api/players/<id>/career/` and `GET /api/players/benchmarks/` (builders and params: [`api.md`](api.md)).
Moved verbatim from `laserforce_simulator/teams/CLAUDE.md`; the app index there points here.

## HX-01 career stats

A per-player career aggregation of `PlayerRoundState` across every round the player appears in, built by `teams.services.build_career_stats`.

**Pure aggregation module.** `teams/career_stats.py` is the algorithmic seam — **pure Python, no Django imports, no ORM, no RNG, no I/O** (frozen import allowlist: `typing`, `collections`, optional `math`, and `SPECIAL_COST` from `matches.sim_helpers.role_constants`). The Tests agent pins this with a "no Django imports leaked" defensive check mirroring the RES-04 / RV-03 precedent. The module's public surface is four functions:

- `summarize(rounds: Iterable[Mapping]) -> dict` — career totals across every round, returning **exactly** six keys `{games, avg_points, tag_ratio, avg_survival_ticks, avg_accuracy_pct, avg_sp_earned}` (empty input ⇒ `games=0` and every other key `0.0`, no division by zero).
- `summarize_by_role(rounds) -> list[dict]` — per-role breakdown, one entry per role **actually played**, in the locked order Commander/Heavy/Scout/Medic/Ammo (roles not played are omitted; empty input ⇒ `[]`).
- `points_trend(rounds, window=10) -> list[list]` — rolling-mean trend of `points_scored`, returning `[[round_idx, mean_points], …]` with `round_idx` 1-based, sorted ascending by `(date_played, game_round_id)` tiebreaker, partial trailing window for rounds 1..9 and full 10-window for rounds 10+. The `list[list]` (not `list[tuple]`) shape makes JSON serialisation trivial.
- `rolling_mean(values: list[float], window=10) -> list[float]` — the pure helper used internally by `points_trend`, exported so tests can pin it directly without depending on `points_trend` ordering.

**Formulas (frozen, sum/sum where statistically required).** `Tag ratio` = `sum(tags_made) / max(sum(times_tagged), 1)` — sum/sum, **not** mean-of-per-round-ratios; pinned by `test_tag_ratio_is_sum_over_sum_not_mean_of_ratios` against the deliberately-asymmetric `10/1` vs `0/100` two-round case where mean-of-ratios would yield `5.0` and sum/sum yields ≈ `0.099`. `Avg survival ticks` = `mean(min(was_eliminated_at, 1800))` — the cap is TIME-01's `TICKS_PER_ROUND = 1800`, so `SURVIVED_SENTINEL = 1801` contributes 1800. `Avg accuracy` = `sum(tags_made) / max(sum(tags_made + shots_missed), 1) × 100`. `Avg SP earned` = `mean(final_special + SPECIAL_COST.get(role, 0) × specials_used)` — the `.get` fallback contributes **0** for Heavy (which has no `SPECIAL_COST` entry), pinned by `test_avg_sp_earned_mixed_roles_includes_heavy_fallback`.

**Round-dict crossing the service ↔ pure-module seam.** `build_career_stats` assembles a list of plain-dict rounds and hands the list to the pure functions; each dict carries the ten frozen HX-01 keys `{role, points_scored, tags_made, times_tagged, shots_missed, final_special, specials_used, was_eliminated_at, date_played, game_round_id}` (HX-02 adds eight, below) — no aliases. The pure module never sees a Django model, `PlayerRoundState`, `GameRound`, `select_related`, or any ORM type.

**Builder.** `build_career_stats` runs **exactly one** ORM query — `PlayerRoundState.objects.filter(player=player).select_related("game_round").order_by("game_round__date_played", "game_round_id")` — then assembles the round-dict list and calls `summarize` / `summarize_by_role` / `points_trend`; the HX-01 keys are `total_rounds`, `career`, `per_role`, `trend`, `has_rounds` (with `has_rounds = total_rounds > 0`). The API resolves the Player through `get_object()` (unknown / cross-Account ⇒ 404).

**Determinism / scope.** **Read-only** — no RNG, no simulation, no `_flush_to_db` touch, no SIM-07 / SIM-08 contract interaction, no Score Calibration re-baseline obligation. **No model change, no migration**, no ADR (reversible: read-only builder + pure aggregation module), no GLOSSARY.md edit (the **Tag ratio** term was added inline during the grilling session that produced this contract). Tests: `teams/tests/test_career_stats.py::TestCareerStatsPure` for the four pure functions (empty inputs, single-round happy path, sum/sum tag-ratio direction, Heavy `SPECIAL_COST` fallback, `was_eliminated_at=1801` capping to 1800, all-misses accuracy, role ordering Commander/Heavy/Scout/Medic/Ammo, role omission, `rolling_mean` partial-then-full window, `points_trend` `(date, game_round_id)` tiebreaker, and the "no Django imports leaked" defensive check); the endpoint in `teams/tests/test_api_career.py::TestPlayerCareer`. Seam contract: [`.claude/worktrees/hx-01-seam-contract.md`](../../../.claude/worktrees/hx-01-seam-contract.md).

## HX-01b career page 12-stat benchmark extension

Extends the HX-01 per-role breakdown from its original 5 display rows to **15 rows per role actually played** — the original 5 HX-01 display stats plus the 10 net-new HX-02 `STAT_KEYS` rows (the full 12-tuple minus the 2 already overlay-mapped via `_HX01_TO_BENCHMARK_STAT`).

**Frozen 15-row order:** rows 0–4 are the original 5 HX-01 display stats in their current order — `avg_points`, `tag_ratio`, `avg_survival_ticks`, `avg_accuracy_pct`, `avg_sp_earned` — followed by rows 5–14, the 10 net-new `STAT_KEYS` in declaration order skipping `points_scored` and `accuracy`: `mvp`, `tags_made`, `times_tagged`, `final_lives`, `resupplies_given`, `missiles_landed`, `specials_used`, `follow_up_shots`, `reaction_shots`, `combo_resupply_count`. Locked human labels are `Avg points / Tag ratio / Avg survival / Avg accuracy / Avg SP earned / MVP score / Tags made / Times tagged / Final lives / Resupplies given / Missiles landed / Specials used / Follow-up shots / Reaction shots / Combo resupplies`. The `{key}` field is mixed-namespace by design — HX-01 display keys for rows 0–4, raw STAT_KEYS names for rows 5–14.

**Payload shape (additive).** Each `per_role_with_benchmarks[i]` row gains a `stat_rows: list[dict]` field with exactly 15 ordered entries; each entry is `{key, label, player_value: float, benchmark: dict | None}`. The `benchmark` field is `None` for the 3 HX-01-only derived rows (`tag_ratio`, `avg_survival_ticks`, `avg_sp_earned`) and is a `player_position(...)` result dict (`{benchmark_mean, benchmark_median, delta_mean, delta_median, percentile, qualified, n}`) for the 12 benchmark-backed rows. The existing `benchmarks_by_stat` dict is **preserved verbatim** alongside `stat_rows`.

**Player-value sources.** Rows 0–4 (the 5 HX-01 keys) pull `player_value` directly from the existing `summarize_by_role` row dict — no recomputation. Rows 5–14 (10 net-new) call `compute_career_stat_for_role(player_role_rounds, stat)` from `teams/role_benchmarks.py` — the same helper that already feeds the benchmark percentile path inside `_build_per_role_overlay`, so the subject value and the overlay are guaranteed identical. The frozen row spec lives at module scope in `teams/services.py::_HX01B_STAT_ROW_SPEC` (15-tuple of `(key, label, benchmark_stat | None)`), and `_build_per_role_overlay` iterates it inline.

**Determinism / scope.** **Read-only extension** — no RNG, no simulation, no `_flush_to_db` touch, no SIM-07 / SIM-08 contract interaction, no Score Calibration re-baseline obligation. **Zero diff** to `teams/career_stats.py` (HX-01 pure module, "no new pure-module work"), `teams/role_benchmarks.py`, `teams/role_benchmarks_cache.py`, `teams/signals.py`, `matches/`; no model change, no migration, no ADR, no GLOSSARY.md edit (no new domain terms — `Tag ratio` / `Role benchmark` / `Percentile rank` already defined; the 10 net-new stat names are the same `STAT_KEYS` already documented under HX-02). Seam contract: [`.claude/worktrees/hx-01b-seam-contract.md`](../../../.claude/worktrees/hx-01b-seam-contract.md).

## HX-02 role benchmarks

Per-`(Role, Stat)` **Role benchmark** statistics (mean / median / p25 / p75 / p90 / n) and per-player **Percentile rank** (both terms in [GLOSSARY.md](../../../GLOSSARY.md)) computed over the population of every player's career-average-when-playing-that-Role across the `PlayerRoundState` rows of every Round the requesting Account may see (**UXP-14** — see **Ownership scope** below). Surfaced two ways: the standalone per-role benchmarks (`build_role_benchmarks`, `GET /api/players/benchmarks/`) — one table per role across all 12 `STAT_KEYS` — **plus** an additive overlay on the HX-01 career payload that decorates each per-role stat with mean/median/delta/percentile/n.

**Pure aggregation module.** `teams/role_benchmarks.py` is the algorithmic seam — **pure Python, no Django imports, no ORM, no RNG, no I/O** (frozen import allowlist: `bisect`, `statistics`, `collections.defaultdict`, `typing.Iterable`/`Mapping`). The "no Django imports leaked" defensive check mirrors the HX-01 / RES-04 / RV-03 precedent. Module-level constants: `STAT_KEYS` (12-tuple in frozen order — `points_scored, tags_made, times_tagged, accuracy, shots_missed, final_special, specials_used, mvp, final_lives, resupplies_given, missiles_landed, follow_up_shots, reaction_shots, combo_resupply_count`), `RATIO_STATS = frozenset({"accuracy"})`, `MVP_DERIVED_STATS = frozenset({"mvp"})`, `ROLES = ("commander", "heavy", "scout", "medic", "ammo")`. The public surface is six functions: `build_role_populations(rounds, *, threshold=0)`, `apply_threshold(populations, *, threshold)`, `summarize_population(values)`, `percentile_for(values, x)`, `compute_role_benchmarks(rounds, *, threshold=0)`, and `player_position(populations, role, stat, x)`.

**Aggregation rule.** Per-round mean for every stat in `STAT_KEYS` **except** `accuracy`, which uses the Tag-ratio-style sum/sum shape `sum(tags_made) / max(sum(tags_made + shots_missed), 1)` per-player within that role's subset (mirroring the HX-01 `Avg accuracy` formula). The service-side pre-computed `mvp` (from `calculate_mvp`) is treated as a per-round value and rolled up with the same per-round-mean rule as every other counter — the seam carries `mvp` already-computed so the pure module never touches MVP weight logic.

**Subject-inclusion policy.** Mean / median / percentile are computed over the FULL population INCLUDING the subject, so the standalone row and the HX-01-overlay cell for the same player are **guaranteed identical** (no off-by-one between an "all players" framing on the standalone benchmarks and an "all other players" framing on the per-player overlay). Population maximum maps to `100.0`. Below-threshold subjects (`player_position` returns `qualified=False`) render `— (need N+ rounds)` on the SPA career screen, substituting the active `threshold` value.

**Query params.** `?threshold=<int>` (default `5`) and `?display=mean|median` (default `mean`), bound strictly by `BenchmarkParamsForm` (bad values are 400, see [`api.md`](api.md) **Analytics reads**). Threshold gates *visibility* per `(role, stat)` row, not the underlying cached samples.

**HX-01 → STAT_KEYS overlay mapping (v1).** Only `avg_points → points_scored` and `avg_accuracy_pct → accuracy` map onto a STAT_KEYS entry and so receive benchmark cells in `benchmarks_by_stat`; the other three HX-01 display stats (`tag_ratio`, `avg_survival_ticks`, `avg_sp_earned`) get all-`None` placeholders (**HX-01b** extends the per-role rows to the full 12-row set so every benchmarked stat surfaces its overlay). `tag_ratio` / `avg_survival_ticks` / `avg_sp_earned` remain HX-01-only derived stats — they are not in `STAT_KEYS` and HX-02 does not benchmark them.

**Round-dict crossing the service ↔ pure-module seam.** `teams.services._round_dict_from_state` builds a strict **18-key SUPERSET** of HX-01's 10-key dict — additive, with HX-01 signatures unchanged: the 10 HX-01 keys (`role, points_scored, tags_made, times_tagged, shots_missed, final_special, specials_used, was_eliminated_at, date_played, game_round_id`) plus **6 HX-02 raw counters** (`final_lives, resupplies_given, missiles_landed, follow_up_shots, reaction_shots, combo_resupply_count`, all int) plus **2 service-side pre-computed floats** (`mvp` via `PlayerRoundState.get_mvp` / `calculate_mvp`, `accuracy_pct` via `PlayerRoundState.get_accuracy`). The pure module never sees a Django model — only plain dicts.

**Ownership scope (UXP-14).** Benchmarks are **per Account**, not global: the population is the Rounds `owned_game_round_q(user)` admits — the Account's own plus **Unmanaged** Rounds, the same visibility as the rest of the Sandbox ([ADR-0038](../../adr/0038-accounts-and-uniform-manager-ownership.md)). Another Account's Rounds never feed the numbers, on the benchmarks endpoint or the career overlay. `user` is a **required keyword** on `build_role_benchmarks`, `build_career_stats`, `get_all_benchmark_data`, `get_role_benchmark_samples` and `compute_benchmarks_uncached` (no caller can silently fall back to a global scan); an anonymous / `None` user sees Unmanaged Rounds only. Tests: `teams/tests/test_role_benchmarks_ownership.py`.

**Cache helper.** `teams/role_benchmarks_cache.py` exposes `get_all_benchmark_data(*, user)`, `get_role_benchmark_samples(role, stat, *, user)`, and `invalidate_role_benchmarks()`. Backing store is the Django cache framework keyed by a global version int: `role_benchmark_version` holds the int; `role_benchmark:v{version}:{scope}:{role}:{stat}` holds per-`(role, stat)` raw samples, where `{scope}` is `u{account_pk}` or `unmanaged` (UXP-14), so one Account's cached cells are never served to another. The version stays global, so any write busts every scope. A **single full-table scan on miss** populates every `(role, stat)` key for all 5 roles × 12 stats in one pass — second request for any cell post-invalidation is a hit (via `cache.get_many`, one round-trip for all 65 keys). Cached samples are **threshold-independent**: `apply_threshold` runs per request against the cached raw populations, so toggling `?threshold=` does not bust the cache. Invalidation is performed exclusively via `invalidate_role_benchmarks()` (which schedules the version bump under `transaction.on_commit` so a pre-commit reader can't repopulate the cache with not-yet-committed-stale data, then bumps `role_benchmark_version`), never by deleting individual keys. **Cache-miss cost scales with the Account's visible `PlayerRoundState` row count, not the requesting player** — the first `/api/players/<id>/career/` or `/api/players/benchmarks/` request per Account after any write triggers a scan to repopulate that Account's cells; subsequent reads under the same version are cache-only.

**Signal handler + simulator hook.** `teams/signals.py::_bump_role_benchmark_version` registers `post_save` + `post_delete` on `PlayerRoundState` and calls `invalidate_role_benchmarks()` on every save / delete. **Crucially**, `BatchSimulator._flush_to_db` writes via `bulk_create`, which **does not fire `post_save`**, so the signal alone would miss every batch-simulated round — the simulator therefore performs a one-line **lazy-import** call to `invalidate_role_benchmarks()` immediately before its final return. The lazy import inside `_flush_to_db` avoids any `teams ↔ matches` circular-import risk; this is the **only** simulator change for HX-02 and it does not touch any simulation mechanic.

**Empty-population UX.** `any_data` is false when **every** `(role, stat)` returns `n=0` after the threshold; the SPA Role benchmarks screen then shows a notice. **UXP-14:** with `threshold > 0` it names the real gate and the active value — *"No benchmarks yet: a player needs at least N saved Round(s) in a role to count. Lower **Min rounds in role** above to include players with fewer Rounds."* — and with `threshold=0` it reads *"No saved Rounds yet. Play and save some Rounds first."*

**Payload keys.** `build_role_benchmarks` returns `{min_rounds, display, roles, benchmarks, stat_keys, any_data}` (plus `benchmarks_by_role`, which the API drops); `build_career_stats` extends the HX-01 keys additively with `{min_rounds, display, stat_keys, per_role_with_benchmarks}`.

**Determinism / scope.** **Read-only** — no RNG, no simulation, no `_flush_to_db` simulation change (the one-line `invalidate_role_benchmarks()` cache-bust is a cross-cutting hook, not a simulation mechanic), **no SIM-07 / SIM-08 contract interaction, no Score Calibration re-baseline obligation**. **No model change, no migration, no ADR** (decisions are reversible — pure module + cache helper + read-only builders + a one-line simulator cache-bust), no GLOSSARY.md edit (the `Role benchmark` and `Percentile rank` terms were added inline during the grilling session that produced this contract).

Locked names — pure module `teams/role_benchmarks.py`; cache helper `teams/role_benchmarks_cache.py`; signal handler `teams/signals.py::_bump_role_benchmark_version`; simulator hook `invalidate_role_benchmarks()` call inside `BatchSimulator._flush_to_db`; test files `teams/tests/test_role_benchmarks.py` + `teams/tests/test_role_benchmarks_cache.py` + `teams/tests/test_api_career.py`; cache keys `role_benchmark:v{version}:{scope}:{role}:{stat}` + `role_benchmark_version`.
