## LG-01h global nav restructure

**Mode-based base.html restructure** + **19 placeholder pages behind a single shared `coming_soon` view** + **sidebar shape expansion from 14 to 23 entries**, all driven by a new `core.context_processors.app_mode` path-prefix rule that distinguishes league-mode pages (`/leagues/*`, `/seasons/*`) from sandbox-mode pages (everything else, including `/`, `/teams/`, `/players/`, `/matches/`, `/maps/`, `/help/*`, `/tools/*`). LG-01h fulfils the LG-01h promise that LG-01f's partial skeleton stepped toward — see [ADR-0017](../../adr/0017-league-context-nav-shape.md) §4 — without breaking any of the LG-01f / LG-01g surfaces. **No model change, no migration, no new pure module, no simulator touch, no RNG, no `_flush_to_db` touch, no SIM-07 / SIM-08 contract interaction, no Score Calibration re-baseline, no new ADR, no GLOSSARY.md edit, no JS framework, no Celery, no `messages.*`, no API endpoint, no new dependency, no admin change.**

**Mode-detecting context processor.** `core.context_processors.app_mode(request: HttpRequest) -> dict[str, str]` is APPENDED to the LG-01f-created `core/context_processors.py` (NOT a new file). Returns the single-key dict `{"app_mode": "league" | "sandbox"}` via the locked path-prefix rule: `request.path.startswith("/leagues/") or request.path.startswith("/seasons/")` ⇒ `"league"`; everything else ⇒ `"sandbox"`. Reads via `getattr(request, "path", "/")` so a `RequestFactory()`-built request without `.path` doesn't crash. Registered in `settings.TEMPLATES[0]["OPTIONS"]["context_processors"]` **immediately after** `core.context_processors.league_nav` (locked order — `league_nav` first, `app_mode` second). Locked literals `"league"` and `"sandbox"` and the locked context key `app_mode`.

**Base.html mode branching.** `templates/base.html` is MODIFIED — the existing `<div class="navbar-nav ms-auto">` block (LG-01a `Leagues` link replaced by the LG-01f `League ▾` dropdown plus the 6 LG-01a flat sandbox links) is restructured around `{% if app_mode == "league" %}` / `{% else %}`. **League mode** renders, in pinned left-to-right order: brand link (unchanged, `{% url 'landing' %}`), then `League ▾` (LG-01f dropdown preserved, all 5 items now LIVE), then `Help ▾` (NEW), then `Tools ▾` (NEW). **Sandbox mode** renders the brand link, then the 6 LG-01a flat sandbox links in their existing left-to-right order (Teams / Players / Matches / Batch Sim / Create Team / Maps — verbatim `<a class="nav-link" href="{% url '…' %}">` from current `base.html` lines 30–35), then `League ▾`, then `Help ▾`, then `Tools ▾`. The LG-01a-locked outer wrapper `<div class="container">` + `<button class="navbar-toggler">` + `<div class="collapse navbar-collapse" id="mainNav">` markup is preserved verbatim around both branches. The LG-01a-locked DOM id `leagues-nav-link` on the dropdown toggle and the LG-01f-locked DOM id `league-history-topbar-link` on the History `<a class="dropdown-item">` are preserved verbatim in both branches.

**Shared placeholder view.** NEW view `matches.views.coming_soon(request: HttpRequest, feature_key: str, league_id: int | None = None, team_id: int | None = None) -> HttpResponse` is the single shared `<h1>Coming soon</h1>` view for every placeholder URL. Undecorated, GET-only via `if request.method != "GET": return HttpResponseNotAllowed(["GET"])` as the **first** line of the body (LG-01c / LG-01d / LG-01e / LG-01f / LG-01g locked pattern). Body in pinned order: (1) 405 guard before any ORM hit; (2) when `league_id is not None` ⇒ `league = get_object_or_404(League, pk=league_id)` else `league = None`; (3) `team_id` kwarg reserved for forward-compat with LG-02+; (4) `feature = _FEATURE_REGISTRY.get(feature_key)` ⇒ `Http404(f"Unknown placeholder feature {feature_key!r}.")` when `None`; (5) when `league is not None` write `request.session["last_league_id"] = league.id` (extends the LG-01f session-write site list); (6) `displayed_season = league.active_season or league.seasons.filter(state="completed").order_by("-id").first()` when `league is not None`, else `None`; (7) `sidebar_active = feature["sidebar_active"]` (a literal from the 23-entry enum or `None`); `sidebar_links = _build_league_sidebar_links(league, displayed_season, sidebar_active)` when `league is not None`, else `sidebar_links = []` (Help / Tools placeholders render with an empty sidebar — sandbox-mode pages); (8) `return render(request, "_placeholder.html", context)` with the locked **7 context keys** `league` / `displayed_season` / `feature_key` / `feature_label` (= `feature["label"]`) / `feature_section` (= `feature["section"]`) / `sidebar_links` / `sidebar_active`. The view lives in `matches/views.py` even for the Help / Tools entries (single shared view; no `core/views.py` duplication).

## LG-01i Season "One Week (Live)" play-now-and-watch replay

The manager-mode live surface over the LG-01d Play dropdown — a **"One Week (Live)"** entry that **plays `League.current_team`'s next game immediately** (committing it), kicks off the **rest** of the matchday / bracket stage as a **background** run, and opens a read-only **replay** of the just-played game (the SIM-05 client playback engine, fed from the *persisted* event log). The locked model is **play-now-and-watch, NOT preview-then-commit and NOT server-side tick streaming**: results are **final the moment the action runs** — there is **no preview, no commit step, no discard, no retry**. Because the manager's game is committed by the existing per-Round / per-Match sim path with no injected seed, this slice is a thin **view + template + serializer-reuse** layer: **no model change, no migration, no engine-mechanics change, no Score Calibration re-baseline**. The **One Week (Live)** glossary term (above **Current team** in GLOSSARY.md `### League and seasons`) carries the domain language. Seam contract (historical — describes the superseded preview-then-commit design): [`.claude/worktrees/lg-01i-one-week-live-seam-contract.md`](../../../.claude/worktrees/lg-01i-one-week-live-seam-contract.md).

> **History:** LG-01i originally shipped as a **preview-then-commit** flow (an in-memory preview held as a session-pinned RNG seed, watched, then committed or discarded — with an injected-seed seam `rng_seed=` / `rng_seeds=` on the sim methods + `preview_scheduled_round` / `preview_tournament_match` / `_serialize_events_for_preview`). A follow-up redesign **replaced** it with the play-now model below; the preview methods, the injected-seed kwargs, the session pin, and the commit/discard views were all **removed**. The seam contract + the original PLAN note predate that change.

**Two watchable cursor types.** (1) **RR cursor** — `current_team`'s **single next-matchday Round**. A **bye** that matchday ⇒ no game to watch (the action just runs the week in the background, then redirects to the dashboard). (2) **Playoff cursor** — `current_team`'s **next undecided 2-Round playoff Match** (the next undecided `BracketNode` it occupies, `series_matches.count() == 0`), offered ONLY while that team is **alive** (an incomplete, non-bye node it participates in). Eliminated / not-a-participant ⇒ no live entry.

**Two views (`matches/league_views.py`).** (a) **`play_week_live(request, season_id) -> HttpResponse`** — **POST-only** (`HttpResponseNotAllowed(["POST"])` first line), `get_object_or_404(Season)`, sets `request.session["last_league_id"]`; non-active ⇒ `_render_season_dashboard_error(...)` (400 dashboard re-render); resolves the live cursor; an `rr_bye` cursor ⇒ `play_season_task.delay(season.id, max_matchdays=1)` + redirect to `season_dashboard`; no live entry ⇒ 400. Otherwise (inside a `try` catching `ValidationError`/`ValueError` → 400): **RR** resolves the fixture's arena map (`ArenaMap.in_bulk(starting_map_pool_ids_json)` + `matches.tasks._resolve_fixture_map`) and plays the manager's Round via `BatchSimulator().simulate_scheduled_round(...)` ⇒ `round_ids = [game_round.id]`; **playoff** plays the manager's node via `tournament_engine.play_specific_node(node)` then reads the just-played Match's 2 `game_rounds` (the node's latest `series_matches` row) ⇒ `round_ids = [r1, r2]`. Then it **enqueues `play_season_task.delay(season.id, max_matchdays=1)`** to play the rest of the matchday / drain the rest of the bracket stage in the **background** (the task skips the manager's just-played game via its played-keys / `find_next_playable_node` checks), stashes `request.session["live_watch"] = {"season_id", "kind", "round_ids"}` (just "what to show" — the game is already committed, NOT a retry pin), and **redirects** to `play_week_live_watch` ⇒ **302**. (b) **`play_week_live_watch(request, season_id) -> HttpResponse`** — **GET-only** (405 otherwise), 404 on missing Season, reads the `live_watch` session handoff (400 dashboard re-render when absent / for another Season / empty), loads the committed `GameRound`(s), builds the SIM-05 `(events_data, players_data)` payload from the **persisted** events via the reused `matches.views.round_playback_payload(game_round, include_movement=False)`, and renders `templates/seasons/play_week_live.html` ⇒ **200**.

**`round_playback_payload` (reused committed-events serializer).** `matches/views.py::round_playback_payload(game_round, *, include_movement=True) -> (events_data, players_data)` is **extracted from `game_round_events`** (which now calls it) so the watch view reuses the exact same 13-key `events_data` (`type, ts, tf, icon, desc, pts, aid, an, at, tid, tn, tt, meta`) + 6-key `players_data` (`{id, name, team, role, sl, ss}`) serialization the SIM-05 playback engine consumes. `include_movement=False` drops `event_type="movement"` rows (the live watch shows only gameplay events on its timeline; the scoreboard reconstruction ignores movement either way).

**Cursor dispatch.** `matches.league_views._resolve_live_cursor(season) -> dict | None` and `_alive_playoff_node(tournament, team) -> "BracketNode | None"` are unchanged from the original slice: `_resolve_live_cursor` returns a `{"kind": "rr"|"playoff"|"rr_bye", ...}` descriptor (RR carries `fixture` / `season_phase` / `red_team` / `blue_team`; playoff carries `node` / `tournament` / `red_team` / `blue_team`) or `None`; `_next_matchday_to_play(season) -> (to_play, phase_by_id)` is the shared next-matchday-fixtures helper. `_alive_playoff_node` selects the lowest `(_BRACKET_RANK[bracket_type], bracket_round, position)` undecided non-bye node the team occupies with no Series started (`select_related("team_a","team_b")`).

**Engine — `play_specific_node` (no injected seed).** `matches/tournament_engine.py::play_specific_node(node) -> "BracketNode | None"` (`@transaction.atomic`) is the per-Match resolve/advance body extracted from `play_next_node` (which delegates to it). It takes the node **directly** so the live-watch playoff path can play the manager's **specific** node; `play_next_node` plays the next playable one. (No `rng_seeds` — the redesign removed the injected-seed seam.)

**URLs (`matches/season_urls.py`), before `standings/` / `schedule/`, bare names:** `play_week_live` (`/seasons/<int:season_id>/play-week-live/` → POST) and `play_week_live_watch` (`.../watch/` → GET).

**Template `templates/seasons/play_week_live.html`.** Extends `base.html`, `d-flex` + league-sidebar shell (`sidebar_active=None`). It **duplicates** the minimal SIM-05 playback block (scrubber DOM + the `pbPlayers`/`pbEvts`/`pbApply`/`pbSetTime`/`pbRefresh` engine + `MAX_MISSILES` role constant + the `events-data`/`players-data` json_script reads) — NOT extracted into a shared partial, because the SIM-05 engine in `game_round_events.html` is coupled to page-specific `{{ round.* }}` context + the charts / kill-feed / timeline-window pager. Team identity is fed from the per-round `red_team_id` / `red_team_name` / `blue_team_id` / `blue_team_name`. **Scoreboard reads each event's authoritative `actor_`/`target_` metadata snapshots** (`actor_shots`/`actor_lives`/`actor_points`/`sp`, `target_shots`/`target_lives`/`target_points`) for exact shots/lives/score/SP — NOT re-derived — and decrements **missiles** (role-fixed `MAX_MISSILES`, Commander/Heavy 5) on each `locking` event; a resupply / down flashes the respawn colouring. A **role-paired combined scoreboard** (each row pairs the two teams' same-role players, sorted by a canonical role order; a per-team **Missiles** column; three down-state row colourings) plus a **play-synced event timeline** (feed-style, newest at the bottom) and a **"Game start" anchor** (the page opens on a pre-event cursor so the tick-0 events aren't pre-applied). **NO commit / discard controls** — only a **"Back to dashboard"** link (DOM id `play-week-live-done`). **LOCKED DOM ids:** `play-week-live-container`; the reused `pb-*` ids (`pb-time-display`/`pb-scrubber`/`pb-step-back`/`pb-play`/`pb-step-fwd`/`pb-speed`/`pb-scoreboard`/`pb-timeline`); `play-week-live-round-toggle` (+ `play-week-live-round-1`/`-round-2`, playoff only); `play-week-live-done`. **`json_script` ids:** RR emits `events-data` / `players-data`; playoff emits `events-data-1`/`players-data-1`/`events-data-2`/`players-data-2`.

**Dashboard wiring.** Context key **`live_preview_available: bool`** in `_build_dashboard_context` — `True` iff `_resolve_live_cursor(season)` returns a `"rr"` / `"playoff"` descriptor (NOT `None` / `"rr_bye"`). The dropdown entry is a **POST `<form>`** (id `season-dashboard-play-one-week-live` / `league-dashboard-play-one-week-live`) to `play_week_live`, rendered ONLY when `live_preview_available`, alongside the LG-01d One Week / Two Months / Until-End entries. *(RETIRED by NAV-01: the One Week Live entry relocates to the `Play ▾` topnav as `topbar-play-one-week-live`, gated on the same `live_preview_available`; `live_preview_available` is now emitted by `_build_play_controls_context` rather than `_build_dashboard_context`. See **NAV-01** above.)*

**Scope-out (LOCKED).** No model change, no migration, no ADR, no engine-mechanics change, no Score Calibration re-baseline. No preview / commit / discard / retry. No server-side tick streaming. No watching non-manager games (only `current_team`'s game has a replay surface; the rest run headless in the background). No playoff-live when eliminated. No SIM-05 partial extraction (the playback JS is duplicated).

**Locked names (quick index).** Views `matches.league_views.play_week_live` (POST 302 / 400 / 405) / `play_week_live_watch` (GET 200 / 400 / 405); cursor helpers `_resolve_live_cursor` / `_alive_playoff_node` / `_next_matchday_to_play`; engine `tournament_engine.play_specific_node(node)` (extracted from `play_next_node`); serializer `matches.views.round_playback_payload(game_round, *, include_movement=True)`; URLs `play_week_live` (`/seasons/<id>/play-week-live/`) / `play_week_live_watch` (`.../watch/`); session handoff `request.session["live_watch"]` = `{season_id, kind, round_ids}`; background task `play_season_task.delay(season_id, max_matchdays=1)`; context key `live_preview_available`; template `templates/seasons/play_week_live.html` (DOM ids above); tests `TestLg01iCursorDispatch` / `TestLg01iPlayWeekLive` / `TestLg01iLiveWatch` in `views_tests.py`, `TestLg01iDashboardEntry` in `test_league_dashboard.py` / `test_season_dashboard_view.py`.
