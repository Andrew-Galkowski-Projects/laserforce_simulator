## CAR-02 manager firing (owner mood)

Manager-mode performance firing, implemented as a **ZenGM-faithful owner-mood model** (NOT a single configurable threshold — the PLAN's "configurable threshold" wording was superseded at grilling). The team **Owner** judges the **Manager** (the implicit local user = `League.current_team`, CAR-01 — **no `Manager`/`User` model**) once per completed Season across **three cumulative Mood factors** (*wins* / *playoffs* / *money*), fires the Manager when summed mood `<= -1` strictly past a 2-Season Grace period, and routes a fired Manager through a **New Team** picker (worst-5 eligible, old team excluded) before the pre-season rollover can run. **No simulator change → no Score Calibration re-baseline.** Decision: [ADR-0026](../../adr/0026-manager-firing-owner-mood.md). Seam contract: [`.claude/worktrees/car-02-performance-based-firing-seam-contract.md`](../../../.claude/worktrees/car-02-performance-based-firing-seam-contract.md).

**Pure module `matches/owner_mood.py`.** Django-free, **frozen import allowlist** `dataclasses` / `typing` / `collections` ONLY — NO Django / ORM / `random` / `datetime` / `math` / I/O / logging (defended by `TestNoDjangoImportsLeaked`, the subprocess fresh-import + `sys.modules` walk mirroring `season_awards.py` / `development.py` / `standings.py`). Constants (LOCKED values): `WINS_FACTOR = 1.0`, `WINS_BASELINE_SCALE = 0.25`, `PLAYOFF_TITLE = 0.2`, `PLAYOFF_MISS = -0.2`, `PLAYOFF_ADVANCE_SCALE = 0.16`, `MOOD_FACTOR_CAP = 1.0` (per-factor cumulative ceiling, **upside-only — no negative floor**), `FIRE_THRESHOLD = -1.0`, `GRACE_PERIOD_SEASONS = 2` (flat — ZenGM's +3-if-joined-at-playoffs nuance dropped). Three frozen dataclasses with pinned field order: `MoodDeltas(wins, playoffs, money)` / `MoodTotals(wins, playoffs, money)` (`money` always `0.0` this slice — dormant) / `Verdict(outcome, hot_seat_level)` (`outcome ∈ {"retained", "hot_seat", "fired"}` LOCKED strings; `hot_seat_level` 0 for retained/fired, 1/2 only for hot_seat). **Four pure fns:** `compute_wins_delta(won, games) -> float` (`WINS_FACTOR * WINS_BASELINE_SCALE * (won - games/2) / (games/2)`; **`games == 0` ⇒ `0.0`** no div-by-zero); `compute_playoffs_delta(playoff_result, rounds_won, num_rounds) -> float` (`"champion"` ⇒ `+0.2`, `"seeded"` ⇒ `(0.16/num_rounds)*rounds_won` with **`num_rounds == 0` ⇒ `0.0`**, `"missed"` ⇒ `-0.2`, `"none"` ⇒ `0.0`, unknown string ⇒ `0.0` forgiving); `cap_cumulative(prev_cumulative, delta) -> float` (`min(prev + delta, MOOD_FACTOR_CAP)` — cap on the **upside only**); and **one** decider `decide_verdict(totals, deltas, *, seasons_in_tenure) -> Verdict` returning BOTH the outcome AND the hot-seat level (the firing decision + hot-seat projection share the cumulative total + delta, so splitting them would duplicate the threshold math). `decide_verdict` algorithm (LOCKED): `past_grace = seasons_in_tenure > GRACE_PERIOD_SEASONS`; past-grace `total <= -1` ⇒ `Verdict("fired", 0)`; past-grace `total + delta < -1` ⇒ `("hot_seat", 1)`; past-grace `total + 2*delta < -1` ⇒ `("hot_seat", 2)` (level 1 wins when both hold — checked first); else `("retained", 0)`. Inside the grace period the verdict is **always `"retained"`** regardless of mood. Firing compares `<=`; the hot-seat projections compare `<` (strict, matching the spec).

**Model `matches.models.OwnerEvaluation` + migration `0049_ownerevaluation`.** One **immutable** per-`(League, completed Season)` snapshot, placed in `models.py` immediately after `PlayerSeasonRating`. FKs: `league` (`CASCADE`, `related_name="owner_evaluations"`), `season` (`CASCADE`, `related_name="owner_evaluations"`), `team_managed` (`teams.Team`, `SET_NULL`, `null=True/blank=True`, `related_name="+"` — the Team the Manager ran that Season). Factor fields: `wins_delta` / `playoffs_delta` (pre-cap, this Season only) + `money_delta` (`default=0.0`, **DORMANT — always 0.0**); `wins_total` / `playoffs_total` (per-factor cumulative-capped across the tenure) + `money_total` (`default=0.0`, dormant); `verdict` (`CharField(max_length=16, choices=VERDICT_CHOICES)` = `retained`/`hot_seat`/`fired`), `hot_seat_level` (`PositiveSmallIntegerField(default=0)` 0/1/2), `created_at` (`auto_now_add`). `Meta.ordering = ["league_id", "season_id"]` + a `UniqueConstraint(fields=["league", "season"], name="uniq_league_season_owner_evaluation")`. Migration is **CreateModel-only — NO `RunPython` / `RunSQL` / backfill** (ADR-0026 + the ADR-0004 disposable-data posture, the `0048` / `0029` precedent); existing Leagues get no historical rows, the lazy writer fills them in Season order on first reach. Dependency `("matches", "0048_playerseasonrating")`. **Tenure boundaries + grace derive from the snapshot chain** — a `team_managed` change between two consecutive rows (by Season order) marks a NEW tenure (cumulative + grace reset) — **there is no `tenure_id` field** (firings mutate `League.current_team`, so a past Season's managed team is otherwise unrecoverable). The money column is persisted-but-dormant so a future finance subsystem (PLAN **FIN-01**) lights it up **without a migration**.

**Writer `matches.league_views._ensure_owner_evaluations(league, up_to_season) -> None`.** **Lazy + idempotent.** Ensures an `OwnerEvaluation` row for **every completed Season of `league` up to and including `up_to_season`**, written **oldest→newest in Season order** (so the per-factor caps + cumulatives + tenure derivation are correct), `get_or_create`-keyed on `(league, season)` — a present row is left untouched (NO backfill of Seasons before the first computable one, ADR-0004). It walks `league.seasons.filter(state="completed", id__lte=up_to_season.id).order_by("id")` threading three per-factor running totals + a tenure marker (`prev_team_managed` + a `seasons_in_tenure` counter): for each Season it derives `team_managed` from the snapshot chain (no prior in-tenure row ⇒ `league.current_team`, a `"fired"` prior row ends the tenure so the next row reads `current_team` again — the post-Reassignment team, else inherit the prior row's `team_managed`); resets the running totals + `seasons_in_tenure = 1` on a tenure change else `+= 1`; builds the flat inputs (§ below) → `compute_wins_delta` / `compute_playoffs_delta` (`money_delta = 0.0`); cap-chains `cap_cumulative(running.*, delta)`; calls `decide_verdict(MoodTotals(...), MoodDeltas(...), seasons_in_tenure=...)`; and `get_or_create`s the row. **Idempotency note:** when a row already existed, the writer re-reads its **persisted** deltas/totals/`team_managed` into the running state before continuing (the persisted row, not a recompute, is the source of truth for prior Seasons).

**Flat-input assembly (view-side, per Season) — REUSE the standings path.** *wins / games:* reuse `Season._final_standings_for_phase(season.ordered_phases()[-1])` to read the regular-season `StandingsRow` for `team_managed.id` → `won = row.wins`, `games = row.matches_played` (the standings query already excludes playoff Matches — they carry `season=NULL`). *playoffs:* locate the Season's `tournament` `SeasonPhase` (`phase_type == "tournament"`, `tournament_id is not None`); none ⇒ `("none", 0, 0)`; else `num_rounds = max(bracket_round)`, classify `champion` (`tournament.champion_id == team_managed.id`) / `seeded` (in bracket, not champion; `rounds_won` = count of distinct `bracket_round`s with a `BracketNode.winner_id == team_managed.id`) / `missed` (cut / not seeded). The pure module receives only `(won, games)` + `(playoff_result, rounds_won, num_rounds)` — never a Django object.

**`next_season` refactor + verdict gate.** The existing `@transaction.atomic next_season` rollover body (create the new draft Season, carry teams / map pool / phases, `_develop_league_for_new_season`) is extracted **verbatim** into a plain (undecorated) `_run_season_rollover(league, latest_completed) -> Season` shared by BOTH `next_season` and `reassign_team` (each owns its own atomic boundary). `next_season` (still `@transaction.atomic`) becomes the **verdict gate**: after the unchanged 405 / 404 / active-Season-guard / `latest_completed`-resolve steps it calls `_ensure_owner_evaluations(league, latest_completed)`, reads the `(league, latest_completed)` eval, and — **if `verdict == "fired"` AND the Manager has not yet reassigned** (`league.current_team` still == the row's `team_managed`) — **redirects to `new_team_picker`** (a fired-and-unreassigned Manager cannot roll); else runs `_run_season_rollover` + redirects to the new Season's dashboard. **Byte-equivalence guarantee:** for a non-fired Manager the rollover output is byte-equivalent to today — the only added work is the ensure write + the verdict read, which never touch the rollover body.

## CAR-03 career isolation from multiplayer

A **defensive gate only** layered on CAR-02 — the entire owner-evaluation / firing / reassignment lifecycle is made **inert unless `League.mode == "league"`**. The gate predicate is a **positive allowlist** `mode == "league"`, so `"sandbox"`, `"multiplayer"`, and **any future mode** are inert by default (a new mode is non-career until explicitly allowlisted). **No multiplayer creation flow, no new mode value, no model / migration / simulator change, no Score Calibration re-baseline, no new ADR, no new GLOSSARY.md term** (the **Owner evaluation** glossary entry already carries the league-mode-only clause). Seam contract: [`.claude/worktrees/car-03-career-isolation-seam-contract.md`](../../../.claude/worktrees/car-03-career-isolation-seam-contract.md).

**Shared helper (single source of truth).** `matches/league_views.py::_is_career_league(league) -> bool` is the **one** predicate (`return league.mode == "league"`), consumed by the writer, the two reassign views, and the dashboard context — there is no other place that branches on mode for the firing lifecycle.

**Writer chokepoint + two view guards (400).** The lazy writer `_ensure_owner_evaluations(league, up_to_season)` now **early-returns on its first line** when `not _is_career_league(league)` — the chokepoint: **no `OwnerEvaluation` rows are ever written for a non-career League**, so everything downstream that keys on the evaluation row degrades safely. The two reassign-path views `new_team_picker` (GET) and `reassign_team` (POST) add a `not _is_career_league(league)` guard **after** the `get_object_or_404(League, ...)` (so a bad id still 404s) and **before** any `current_team` write ⇒ **`HttpResponseBadRequest` / HTTP 400**, writing nothing (`HttpResponseBadRequest` is already imported in `league_views.py`).

**`next_season` / `owner_evaluation` UNCHANGED.** Neither is guarded — the writer no-op is sufficient. `next_season`'s verdict gate reads `evaluation is None` for a non-career League and **rolls the Season normally** (no firing, no New-Team redirect), byte-equivalent to pre-CAR-02. `owner_evaluation` naturally raises its existing `Http404` on the missing evaluation row for a non-career completed Season (the natural 404 suffices — no explicit guard added).

**Dashboard split (`is_career_mode`).** `_build_dashboard_context(displayed_season, season_mode)` gains an `is_career_mode: bool` key (`displayed_season is not None and _is_career_league(displayed_season.league)`; reachable only on the `start_next_season` branch, where `displayed_season` is the completed Season). Both `templates/seasons/dashboard.html` and `templates/leagues/dashboard.html` split the `start_next_season` arm on it: **`{% if is_career_mode %}`** → the CAR-02 owner-evaluation GET link (`{season,league}-dashboard-owner-evaluation-link`); **`{% else %}`** → a direct `next_season` POST `<form>` (`{season,league}-dashboard-next-season-form`, the pre-CAR-02 LG-01e shape, `league_id` = `season.league_id` / `league.id`). The outer `{season,league}-dashboard-action-button` wrapper `<span>` and `data-action-state="start_next_season"` are **preserved in BOTH arms** (LG-01c/e back-compat).

**Tests** extend the existing CAR-02 files with a representative **`mode="multiplayer"`** fixture (Django `TestCase`, real views/writer end-to-end, no ORM mocks; assert on row counts / status codes / `current_team` / rendered DOM ids, never point totals): `test_owner_evaluations_writer.py` (writer on a multiplayer completed Season writes **0** rows) + `test_league_next_season.py` (`next_season` → **302** to the new Season's dashboard, new draft Season exists, **no** `OwnerEvaluation` row, `current_team` unchanged) + `test_reassign_team.py` (`reassign_team` POST **400** + `new_team_picker` GET **400**, `current_team` unchanged) + `test_league_dashboard.py` / `test_season_dashboard_view.py` (multiplayer completed-Season dashboard renders `…-next-season-form` and NOT `…-owner-evaluation-link`; `league` mode still renders `…-owner-evaluation-link` and NOT the form).

**Locked names (quick index).** Helper `matches.league_views._is_career_league(league) -> bool` (predicate `league.mode == "league"`); guarded sites `_ensure_owner_evaluations` (early-return) / `new_team_picker` / `reassign_team` (400) / `_build_dashboard_context`; dashboard context key `is_career_mode`; dashboard DOM ids (non-career arm) `{season,league}-dashboard-next-season-form`; UNCHANGED `next_season` / `owner_evaluation`; tests extended `test_owner_evaluations_writer.py` / `test_league_next_season.py` / `test_reassign_team.py` / `test_league_dashboard.py` / `test_season_dashboard_view.py` (`mode="multiplayer"` fixture); seam contract `.claude/worktrees/car-03-career-isolation-seam-contract.md`.

## FIN-01 team finance subsystem

The finance epic CAR-02 deferred — it **lights up the dormant *money* mood factor** CAR-02 shipped as a permanent `0.0` column on `OwnerEvaluation`. A per-League team finance economy: **player salary** (derived from `overall_rating`), three per-Team **budget** levels (scouting / coaching / facilities) + a ticket price, **season-level profit** accounting (revenue vs expenses, ZenGM's `winp`-driven hype loop, a fixed single market), and the **money-axis wire** that replaces `_ensure_owner_evaluations`'s hardcoded `money_delta = 0.0` / `money_total = 0.0` with a real computed value. Gated by a **per-League `finance_enabled` toggle** ON TOP of CAR-03's `_is_career_league` mode gate; OFF ⇒ the whole subsystem is **inert and byte-identical to today**. **Cost-only this slice** — budgets are pure expense lines (facilities additionally feeds revenue), scouting/coaching buy NO gameplay edge yet (FIN-02/03). **Finances consume no RNG, are outside SIM-07/08, → NO Score Calibration re-baseline.** Decision: [ADR-0027](../../adr/0027-team-finance-subsystem.md). Seam contract: [`.claude/worktrees/fin-01-seam-contract.md`](../../../.claude/worktrees/fin-01-seam-contract.md).

## FIN-02 coaching budget into player development

Lights up the **coaching** budget FIN-01 shipped cost-only (the LG-04 develop knob ADR-0024 shipped **fixed at 0** precisely as this deferral). A Team's effective coaching level now **directionally scales** its players' LG-04 age-curve development at each `next_season` rollover — better coaching speeds development, neglected coaching slows it. **Backend-only** (no UI / template change). **Finance-OFF — or any `coaching_effect=0.0` — develop is byte-identical to LG-04**, and **Potential (LG-05) is untouched** (coaching never touches Potential; FIN-03 owns scouting→potential). Coaching mutates Stat *inputs* for finance-ON leagues only and changes no simulation *mechanic* ⇒ **NO Score Calibration re-baseline**. The GLOSSARY.md **Coaching effect** term + the Budget / Player-development edits are already written. Seam contract: [`.claude/worktrees/fin-02-coaching-development-seam-contract.md`](../../../.claude/worktrees/fin-02-coaching-development-seam-contract.md). Depends on **FIN-01**.

**Mechanism — `matches/development.py::develop_player_stats` (no new RNG draw, no new import).** The signature gains a **keyword-only** `coaching_effect: float = 0.0`: `develop_player_stats(stats, age, rng, *, coaching_effect=0.0) -> dict[str, int]`. The body computes the per-player **effective base change** `effective = base_change(age) + base_change_noise(age, rng)` exactly as LG-04 (the single `gauss` noise draw fires FIRST, unchanged), then — **between that gauss draw and the 19 `develop_stat` `uniform(0.4, 1.4)` draws** — scales it **once**: `effective *= 1 + _sign(effective) * coaching_effect`. **`_sign(x) -> float`** is a tiny NEW module-private helper returning `-1.0` / `0.0` / `+1.0` (a hand-rolled sign so **`math` is NOT imported** — the frozen `dataclasses` / `typing` / `random` / `collections` allowlist holds and `test_development.py::TestNoDjangoImportsLeaked` stays green). The `_sign` factor makes the scale **directional**: a positive `coaching_effect` pushes a *gaining* player further up and a *declining* player **toward 0** (slower decline), a negative effect does the reverse — coaching multiplies the magnitude-with-sign, it is NOT a flat add. The scaled `effective` then flows into the 19 `develop_stat(current, name, age, effective_base_change=effective, rng)` calls **as before** — **`develop_stat` is byte-unchanged**. Because the scale lands **after the gauss and before any uniform draw**, the pinned **1-gauss-then-19-uniform** sequence is **unperturbed** and a seeded develop stays reproducible; **`coaching_effect=0.0` ⇒ multiplier exactly `1.0` ⇒ byte-identical to LG-04** (this is the load-bearing OFF guarantee — pinned by a regression test).

## FIN-05 luxury-tax challenge-mode firing

The **luxury-tax challenge fire** CAR-02 and FIN-01 both deferred — an **optional per-League rule**
(`League.challenge_fired_luxury_tax`, default off, **set at create only, no mid-League edit surface**) that
fires the Manager **outright** any completed Season their Current team pays the luxury tax, **independent of
cumulative owner mood**. The faithful analogue of ZenGM's `challengeFiredLuxuryTax` game attribute. It
**respects the same Grace period** as mood firing and is **checked FIRST inside the past-grace gate** (so it
takes precedence over the mood verdict). Reads the FIN-01 luxury-tax expense line
(`TeamSeasonFinance.luxury_tax`) the writer already fetches. **No simulator change → NO Score Calibration
re-baseline.** Decision: the **FIN-05 Consequences addendum on [ADR-0026](../../adr/0026-manager-firing-owner-mood.md)**
(the ADR that recorded the luxury-tax-firing deferral — **no new ADR**). **No new GLOSSARY.md term.** Seam
contract: [`.claude/worktrees/fin-05-luxury-tax-firing-seam-contract.md`](../../../.claude/worktrees/fin-05-luxury-tax-firing-seam-contract.md).
Depends on **FIN-01** (the payroll + luxury-tax model) and the CAR-02 firing lifecycle.

**Pure decider — `matches/owner_mood.py::decide_verdict` (CHANGED signature).** Gains **two keyword-only
bools, both `default False`** — `luxury_tax_paid` and `challenge_fired_luxury_tax` — so the signature becomes
`decide_verdict(totals, deltas, *, seasons_in_tenure, luxury_tax_paid=False, challenge_fired_luxury_tax=False)
-> Verdict`. A **NEW branch is placed FIRST inside the existing `past_grace` block, BEFORE the mood `total <=
FIRE_THRESHOLD` check**: `if past_grace and challenge_fired_luxury_tax and luxury_tax_paid: return
Verdict("fired", 0)`. **Branch order is load-bearing** — the luxury fire takes precedence *over* the mood
verdict but lives *inside* the same `past_grace = seasons_in_tenure > GRACE_PERIOD_SEASONS` gate (so there is
**no luxury firing during grace**, mirroring mood firing). The mood `total <= FIRE_THRESHOLD` (`<=`) check and
**both** hot-seat projections (`< FIRE_THRESHOLD`, strict; level-1-wins ordering) are **byte-for-byte
identical** to today, only shifted down by the inserted branch. Both new params **default `False` ⇒ ZERO blast
radius** on every existing caller / test (a caller passing neither bool gets exactly today's behaviour). The
module stays **Django-free** — the two new params are plain bools, no new import, so the frozen
`dataclasses`/`typing`/`collections` allowlist **holds** and `TestNoDjangoImportsLeaked` stays green. The
frozen **`Verdict` dataclass is UNCHANGED** (`(outcome, hot_seat_level)`, no `fired_reason`) — the reason is
persisted by the writer onto the row, **never carried through the pure decider**.
